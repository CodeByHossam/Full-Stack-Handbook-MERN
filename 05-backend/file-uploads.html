File Uploads

Getting a file from a React input, through FormData, into Express with Multer, and safely into cloud storage — the client-side and generic server mechanics.

Backend Multer FormData · Validation

The upload flow

An upload travels from a React file input, through FormData, into Express, where Multer parses the bytes and hands them to storage. Only the resulting URL or key is saved in MongoDB, never the bytes themselves.

Note

This page covers the client input, FormData, Multer, validation, and storage strategy. Provider-specific setup for Cloudinary and AWS S3 is owned by File Storage: S3 & Cloudinary.

How HTTP carries text and binary

Every byte a computer stores or sends is binary. Text (like the letters in a form) is binary interpreted through a character encoding such as ASCII or UTF-8, so text and files alike travel inside an HTTP message body. HTTP/1.x uses a textual message format while HTTP/2 and HTTP/3 use binary framing, but in every version the body may hold text or raw bytes.

A Content-Type header tells the server how to interpret that body. There are three practical ways to send a file:

FormatBody isUse when
multipart/form-dataRaw bytes + text fields, separated by a boundaryUploading files together with form fields (default choice)
Base64 inside JSONA text string that encodes the bytesThe API only accepts JSON / text and the file is small
Raw binary bodyThe file bytes directlyA single file with no extra fields (for example PUT /files/image.png)

Multipart wraps each part with a boundary and its own headers, so one request can carry several fields and files:

POST /upload HTTP/1.1
Content-Type: multipart/form-data; boundary=----XYZ123

------XYZ123
Content-Disposition: form-data; name="file"; filename="image.png"
Content-Type: image/png

(binary file bytes here)
------XYZ123--

Base64 turns the same bytes into ASCII text so they can sit inside a JSON field — at the cost of about 33% more size:

{
    "filename": "image.png",
    "data": "iVBORw0KGgoAAAANSUhEUgAA..."
}
Key point

HTTP can send binary directly, so use multipart/form-data for file uploads and reach for Base64 only when a text-only interface (JSON, email) forces it. Base64 is an encoding, not compression or encryption.

For continuous binary streams (live media, long transfers) WebSockets can move raw frames without re-encoding: set ws.binaryType = "arraybuffer" and send a Uint8Array.

File input in React

A file input stays uncontrolled in practice: you read the chosen file from e.target.files in the change handler instead of binding a value prop.

<input
    type="file"
    onChange={handleFileChange}
/>
const handleFileChange = (e) => {
    const file = e.target.files[0]; // first chosen file
    console.log(file);
};

The file object

A selected file carries metadata about itself.

file.name;
file.size;
file.type;
file.lastModified;

console.log(file.name);
console.log(file.size);
console.log(file.type);

Multiple files

Add the multiple attribute so the user can pick several files at once; e.target.files then holds a list you can iterate.

<input
    type="file"
    multiple
    onChange={handleFiles}
/>
const files = e.target.files; // a FileList, not a plain array

files[0];
files[1];
files[2];

FormData

FormData encodes files for transport over HTTP as multipart/form-data.

const formData = new FormData();

formData.append("image", file);

fetch("/api/upload", {
    method: "POST",
    body: formData
});
Common mistake

Do not manually set Content-Type: multipart/form-data. The browser adds the correct boundary automatically; setting it yourself breaks the request.

Send a file plus other data

Because FormData is a key/value container, you can attach text fields alongside the file in one request. The server splits them into req.file (the file) and req.body (the rest).

const formData = new FormData();

formData.append("image", file); // file goes under the "image" field
formData.append("name", "Laptop"); // text fields are fine too
formData.append("price", "1000");

// server receives: image, name, price

Sending with fetch or axios

The same FormData object works with either HTTP client. With axios you pass it directly as the body and the multipart headers are set for you.

// fetch
await fetch("/api/products", {
    method: "POST",
    body: formData // no Content-Type header needed
});

// axios
const formData = new FormData();
formData.append("image", file);
formData.append("name", name);

await axios.post("/api/products", formData); // axios detects FormData

Form submission types and enctype

The enctype attribute (or the Content-Type when you build the request yourself) decides how form fields are encoded before they are sent. Picking the wrong one is why file inputs arrive empty on the server.

TypeUsed for
application/x-www-form-urlencodedDefault for simple text forms
multipart/form-dataRequired when the form includes a file
text/plainRarely used

Plain HTML form (no JavaScript)

A normal form submits itself using its action URL and method. Set enctype="multipart/form-data" whenever a file input is present.

<form action="/plain" method="POST">
    <input type="text" name="username" required />
    <input type="email" name="email" required />
    <button type="submit">Submit</button>
</form>

On the server, url-encoded bodies are parsed with express.urlencoded() (JSON bodies with express.json()).

app.use(express.urlencoded({ extended: true })); // parses application/x-www-form-urlencoded

app.post("/plain", (req, res) => {
    res.json({ message: "Form received", data: req.body });
});

Fetch submission with JSON

When you submit with JavaScript you must serialize the payload yourself. The fetch body has to be a string, so a plain object fails — wrap it in JSON.stringify and send a matching Content-Type.

const data = { username: "Alice", email: "alice@example.com" };

await fetch("/js", {
    method: "POST",
    headers: { "Content-Type": "application/json" }, // server needs express.json()
    body: JSON.stringify(data)                        // body must be a string, not an object
});
Common mistake

Passing a plain object as body sends "[object Object]". Always use JSON.stringify for JSON, or pass a FormData object untouched for multipart.

FormData is iterable, so you can read or convert its entries. This is handy to move values between a multipart form and a JSON API:

const formData = new FormData(formEl);

// iterate every field
for (const [key, value] of formData.entries()) {
    console.log(key, value);
}

// convert to a plain object, then send as JSON
const values = Object.fromEntries(formData.entries());
// values => { name: "Alice", email: "alice@example.com" }

The file-upload variant (a form with enctype="multipart/form-data" posted through FormData and parsed by Multer) is covered above in Multer.

Express does not parse files

express.json() does not process multipart/form-data files. For files you need Multer.

const express = require("express");
const app = express();

app.use(express.json());
// JSON only — files still need Multer

Multer

Multer is Express middleware that reads multipart/form-data bodies and writes uploaded files to disk, memory, or your own handler. Without it, req.file never appears and file fields are dropped.

npm install multer
const multer = require("multer");

// basic usage with a destination folder
const upload = multer({ dest: "uploads/" }); // temp folder, random filenames

app.post("/upload", upload.single("image"), (req, res) => {
    console.log(req.file);
    res.json({ message: "Uploaded" });
});
Key point

The field name "image" must match formData.append("image", file). A mismatch causes a Multer error.

req.file

After upload.single("image"), the uploaded file is on req.file.

req.file.originalname; // client's filename (untrusted)
req.file.mimetype;     // e.g. "image/png" (also untrusted)
req.file.size;         // bytes
req.file.path;         // where disk storage wrote it
req.file.filename;     // the (often random) stored name

req.body

Non-file fields land on req.body, so the server receives both.

// formData.append("name", "Laptop")
req.body.name;

// req.file = the uploaded file
// req.body = the other form data

Multiple files with upload.array

upload.array accepts many files under a single field name and exposes them as an array on req.files. The second argument caps how many are accepted.

upload.array("images", 5); // up to 5 files, all under "images"

app.post("/upload", upload.array("images", 5), (req, res) => {
    console.log(req.files); // an array
});

Different file fields with upload.fields

upload.fields handles several differently-named file fields in one request, each with its own limit. Access them by name on req.files.

upload.fields([
    { name: "avatar", maxCount: 1 },
    { name: "documents", maxCount: 5 }
]);

// then:
req.files.avatar;    // array (maxCount 1)
req.files.documents; // array (maxCount 5)

Memory storage

Keeps the file in RAM as a Buffer — ideal when forwarding straight to a cloud provider.

const storage = multer.memoryStorage();

const upload = multer({ storage });

// req.file.buffer contains the file bytes

Use memory storage with Cloudinary, AWS S3, or other cloud storage — see File Storage: S3 & Cloudinary.

Watch out

Memory storage holds the entire file in RAM. Large files or many concurrent uploads can exhaust server memory, so always pair it with a size limit.

Disk storage

Writes the file to a local folder with a controlled filename.

const storage = multer.diskStorage({
    destination: "uploads/",
    filename: (req, file, cb) => {
        cb(null, Date.now() + "-" + file.originalname); // prefix keeps names unique
    }
});

const upload = multer({ storage });
Watch out

Two files with the same original name overwrite each other unless you generate a unique filename (as above) or a random key.

MiddlewareFile livesBest for
memoryStorage()RAM as req.file.bufferForwarding straight to S3 / Cloudinary
diskStorage()Local disk at req.file.pathServing local files or later processing

File type validation

Do not accept every file type. Validate by MIME type in a fileFilter.

const fileFilter = (req, file, cb) => {
    if (file.mimetype.startsWith("image/")) {
        cb(null, true); // accept
    } else {
        cb(new Error("Only images allowed")); // reject -> surfaces as an error
    }
};

File size limit

An unlimited upload endpoint is a denial-of-service risk. Setting limits.fileSize rejects oversized files before they exhaust memory or disk.

const upload = multer({
    storage,
    limits: {
        fileSize: 5 * 1024 * 1024 // 5 MB maximum, in bytes
    }
});

Security

Never blindly trust file.originalname or file.mimetype. Validate files on the server.

  • File size limits
  • Allowed MIME types
  • Extension validation when appropriate
  • Authentication and authorization
  • Safe generated filenames (avoid the raw original name)
  • Virus/malware scanning where appropriate
  • Rate limiting for public upload endpoints

Database model

The schema stores the file's URL and provider id, not the file itself. Keeping the publicId/key lets you delete or replace the remote file later.

const productSchema = new mongoose.Schema({
    name: String,
    imageUrl: String,     // public URL the frontend displays
    imagePublicId: String // provider id needed to delete/replace
});

Storing publicId lets you later delete or replace the cloud file. Schema basics are owned by MongoDB Basics.

Replace an image

Replacing means deleting the old cloud asset, uploading the new one, and updating the stored URL — otherwise orphaned files accumulate and cost money.

When deleting a product:

  1. Delete the cloud file.
  2. Delete the database document.

Do not leave unused files behind in cloud storage.

File download

res.download streams a local file as an attachment with a Content-Disposition header. Files held in cloud storage are fetched by URL instead.

res.download(filePath); // sets Content-Disposition: attachment

Or redirect/provide a URL to cloud storage. For private files, use signed URLs.

Full basic MERN upload example

A minimal end-to-end example: the frontend posts FormData and the backend parses it with Multer before forwarding the buffer to cloud storage.

Frontend

Build the FormData from the selected file and POST it; the browser fills in the multipart headers.

const formData = new FormData();
formData.append("image", selectedFile);

await fetch("/api/products", {
    method: "POST",
    body: formData
});

Backend

The route uses memory storage so the file arrives as req.file.buffer, ready to stream to a provider, then saves the returned URL.

const upload = multer({ storage: multer.memoryStorage() });

app.post(
    "/api/products",
    upload.single("image"),
    async (req, res) => {
        console.log(req.file);
        console.log(req.body);

        // Upload req.file.buffer to cloud storage

        // Save URL in MongoDB
    }
);

Error handling

Uploads fail for many reasons, so wrap the work in try/catch and forward errors to Express. Handle at least: file too large, invalid type, missing file, and storage or database failure.

try {
    const result = await uploadFile(file);
} catch (error) {
    console.error(error); // or next(error) to reach the error handler
}

The server should handle: file too large, invalid type, missing file, upload failure, cloud storage failure, and database failure. Forward errors to the Express error handler from Express · Error-handling middleware.

Quick recap

  • React <input type="file"> → e.target.files
  • File object: name, size, type, lastModified
  • Wrap files in FormData; never set Content-Type manually
  • HTTP bodies carry text or binary; multipart for uploads, Base64 only for text-only APIs
  • enctype selects the encoding; express.urlencoded() parses plain forms, express.json() parses JSON
  • Multer is required for multipart/form-data
  • single / array / fields → req.file / req.files / req.body
  • memoryStorage gives req.file.buffer; diskStorage writes to disk
  • Validate MIME type and enforce a size limit
  • Store file in cloud storage; store URL + publicId in MongoDB
  • Replace/delete both the cloud file and the document
  • Private files use authentication + signed URLs
