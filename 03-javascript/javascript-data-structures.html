JavaScript Data Structures

Built-in structures (Array, Object, Set, Map, WeakMap, WeakSet) and classic Stack/Queue implementations with guidance.

JavaScript Data Structures

Overview

Data structure = a way to organize and store data for efficient use. Focus on built-ins first; implement classic ones when needed.

Array

Ordered, indexed collection. Mutable; great for lists. Index access is O(1); searching by value is O(n).

const fruits = ["apple", "banana", "orange"];
fruits[0]; // "apple"
fruits.push("mango");
fruits.pop();
fruits.slice(0,2); // copy portion
fruits.splice(1,1); // mutate
When to use

Ordered sequences, rendering lists in UI, iteration with map/filter.

Object

Key-value pairs (string/symbol keys). Common for records/config. Lookup by known key is O(1) on average.

const user = { name: "Alice", age: 30 };
user.name;
user["age"];
Object.keys(user);
Object.values(user);
Object.entries(user);
When to use

Fixed shape data, JSON-like structures, lookups by known keys.

Set

Collection of unique values. Duplicates are silently ignored, and membership checks with has are O(1) on average.

const set = new Set([1,2,2,3]);
set.add(4);
set.has(2); // true
set.delete(1);
set.size;
const unique = [...set];
When to use

Deduplicate arrays, membership checks.

Map

Key-value pairs with keys of any type; preserves insertion order. Unlike objects, keys are not coerced to strings, so numbers and objects work as keys.

const map = new Map();
map.set(1, "Alice");
map.set("id", 123);
map.get("id");
map.has(1);
map.delete(1);
map.size;
When to use

Dynamic keys, object keys that aren’t strings, frequent lookups.

Map vs Object

Both store key-value pairs, but they behave differently. Use a plain {} object for fixed, string-keyed records (and anything you send as JSON), and a Map when keys may be non-strings, insertion order matters, or you insert and delete frequently.

Key coercion in objects

Objects convert keys to strings, so a number key and its string form collide:

const obj = {};
obj[123] = "Number Key";
console.log(obj["123"]); // "Number Key" - the number was coerced to a string

const map = new Map();
map.set(123, "Number Key");
console.log(map.get(123)); // "Number Key" - kept as a real number key

Prototype pollution

Because objects inherit from Object.prototype, a key such as constructor can shadow or be shadowed by inherited members. A Map has no inherited keys and is safe here.

const obj = {};
obj["constructor"] = "Oops!";
console.log(obj.constructor); // [Function: Object] - inherited member, not "Oops!"

const map = new Map();
map.set("constructor", "Safe");
console.log(map.get("constructor")); // "Safe" - no inherited keys interfere
Watch out

Never trust user-supplied keys on a plain object: a key like __proto__ or constructor is a known prototype pollution vector. Use a Map, or Object.create(null), when keys come from untrusted input.

WeakMap & WeakSet

Weak references to objects; keys (WeakMap) must be objects. Not iterable; GC-friendly for caches.

const wm = new WeakMap();
const obj = {};
wm.set(obj, "data");
wm.get(obj);

const ws = new WeakSet();
ws.add(obj);
ws.has(obj);
When to use

Advanced cases (metadata/private-like storage, caches) where you don’t want to prevent GC.

Pick a structure by how you access data: Array for ordered sequences, Object for fixed-shape records, Set for uniqueness, and Map for frequent keyed lookups with any key type.

Iterators & iterables

An iterator is an object that yields values one at a time through a next() method. A collection is iterable when it implements [Symbol.iterator] — the special built-in symbol that returns an iterator. for...of, spread, and destructuring all rely on it. Arrays, Strings, Maps, Sets, Typed Arrays, and generators are iterable by default.

const arr = [10, 20, 30];
const iter = arr[Symbol.iterator](); // get the array's iterator
console.log(iter.next()); // { value: 10, done: false }
console.log(iter.next()); // { value: 20, done: false }
console.log(iter.next()); // { value: 30, done: false }
console.log(iter.next()); // { value: undefined, done: true }

Custom iterable

Implementing [Symbol.iterator] makes your own object work with for...of and spread:

const record = {
    data: { name: "Alice", email: "alice@example.com" },
    [Symbol.iterator]() {
        const entries = Object.entries(this.data);
        let index = 0;
        return {
            next() {
                if (index < entries.length) {
                    return { value: entries[index++], done: false };
                }
                return { value: undefined, done: true };
            }
        };
    }
};
for (const [key, value] of record) {
    console.log(key, value); // name Alice, then email alice@example.com
}

Iterating FormData

formData.entries() returns an iterator, not an array — spread it or convert it before inspecting:

const formData = new FormData(formEl);
console.log([...formData.entries()]);                // view as an array of [key, value]
console.log(Array.from(formData.entries()));         // same, explicit copy
const obj = Object.fromEntries(formData.entries());  // convert to a plain object

Stack (LIFO)

Last In, First Out. Think plates — the last one placed on top is the first removed; push and pop both work on the top end in O(1).

const stack = [];
stack.push("A"); // push
stack.push("B");
stack.push("C");
stack.pop();     // remove top (C)
const top = stack[stack.length-1]; // peek

Array-based Stack implementation

A minimal array-backed Stack. push returns this so calls can be chained.

class Stack {
    constructor() {
        this.items = [];
    }
    push(el) { this.items.push(el); return this; }
    pop() { return this.items.pop(); }
    peek() { return this.items[this.items.length - 1]; }
    isEmpty() { return this.items.length === 0; }
    size() { return this.items.length; }
    clear() { this.items = []; }
    toArray() { return [...this.items]; }
}
const s = new Stack();
s.push(1).push(2).push(3);
s.pop(); // 3
When to use

Undo/redo, call stack simulation, parsing, backtracking.

Queue (FIFO)

First In, First Out. Think a waiting line — the first item to arrive is served first. Enqueue at the rear, dequeue from the front.

const queue = [];
queue.push("A"); // enqueue
queue.push("B");
queue.shift();   // dequeue (A) - O(n) for arrays
const front = queue[0]; // peek

Array-based Queue implementation (efficient front removal)

Removing from the front of an array with shift is O(n). This version tracks a head index so dequeue is O(1), and only compacts the backing array occasionally.

class Queue {
    constructor() {
        this.items = [];
        this.head = 0;
    }
    enqueue(el) { this.items.push(el); return this; }
    dequeue() {
        if (this.isEmpty()) return undefined;
        const val = this.items[this.head++];
        // optional: trim occasionally
        if (this.head > 100 && this.head > this.items.length/2) {
            this.items = this.items.slice(this.head);
            this.head = 0;
        }
        return val;
    }
    front() { return this.isEmpty() ? undefined : this.items[this.head]; }
    isEmpty() { return this.head >= this.items.length; }
    size() { return this.items.length - this.head; }
    clear() { this.items = []; this.head = 0; }
}
When to use

Task scheduling, BFS, request queues, streaming buffers.

At a glance: the two differ only in which end you add to and remove from.

Linked List

A linked list is a chain of nodes, each holding a value and a pointer to the next node. Unlike an array, elements are not stored contiguously, so inserting or deleting in the middle is O(1) once you hold the node — but reaching a position is O(n) because you must walk from the head. Use one when you insert/remove frequently and rarely need random index access.

class Node {
    constructor(value) {
        this.value = value;
        this.next = null;
    }
}

class LinkedList {
    constructor() {
        this.head = null;
    }
    insertAtEnd(value) {
        const newNode = new Node(value);
        if (!this.head) {
            this.head = newNode; // first node becomes the head
            return;
        }
        let current = this.head;
        while (current.next) current = current.next; // walk to the tail
        current.next = newNode;
    }
    deleteValue(value) {
        if (!this.head) return;
        if (this.head.value === value) {
            this.head = this.head.next; // removing the head just moves head forward
            return;
        }
        let current = this.head;
        while (current.next && current.next.value !== value) {
            current = current.next;
        }
        if (current.next) current.next = current.next.next; // unlink the node
    }
    printList() {
        let current = this.head;
        while (current) {
            console.log(current.value);
            current = current.next;
        }
    }
}

const list = new LinkedList();
list.insertAtEnd(10);
list.insertAtEnd(20);
list.deleteValue(10);
list.printList(); // 20
When to use

Dynamic sizes and frequent inserts/deletes in the middle (browser history, graph adjacency lists, queue backings). If you mostly read by index, prefer an Array.

Immutability notes (React)

React detects state changes by reference, so mutating an array/object in place can skip a re-render. Always build a new copy with spread, map, or filter.

// Avoid mutating arrays/objects
// BAD: items.push(x); user.name = "Bob";

// GOOD: spread
setItems([...items, x]);
setUser({ ...user, name: "Bob" });

// GOOD: map/filter
setItems(items.map(i => i.id===id ? {...i, done:true} : i));
setItems(items.filter(i => i.id!==id));

Optional chaining & nullish coalescing

Two operators that make reading possibly-missing data safe: ?. stops at undefined instead of throwing, and ?? supplies a default only when the value is null/undefined (not for 0 or "").

user.address?.city;   // undefined instead of TypeError if address is missing
const name = user.name ?? "Guest"; // "Guest" only when name is null/undefined

Quick recap

  • Array: ordered lists; prefer non-mutating methods in React.
  • Object: key-value records; Map for dynamic keys.
  • Set: unique values; great for dedup.
  • Map: flexible keys, O(1) average lookups.
  • Map vs Object: Map for non-string keys, order, and frequent edits; Object for JSON records.
  • Iterators: any object implementing [Symbol.iterator] works with for...of and spread.
  • Stack (LIFO): push/pop at top.
  • Queue (FIFO): enqueue at rear, dequeue at front.
  • Linked list: nodes chained by next; O(1) insert/delete with a reference, O(n) access.
  • WeakMap/WeakSet: object keys with weak refs (advanced).
