HTML

HyperText Markup Language defines the structure, content and meaning of every web page — the foundation the entire MERN stack renders into.

Frontend Structure & Semantics

What HTML does

HTML defines the structure, content, meaning (semantics), forms, links, images, tables and the accessibility foundation of a page. CSS handles appearance and JavaScript/React handles behavior.

TechnologyResponsibility
HTMLStructure & meaning
CSSAppearance / layout
JavaScriptBehavior
ReactComponents + state
Key point

Don't ask "which tag makes this look right?" Ask "what is the meaning of this content?" — choose elements for meaning, then style with CSS. See CSS.

Document structure

Every HTML document follows the same skeleton: a doctype, the <html> root, a <head> with metadata, and a <body> with visible content.

<!DOCTYPE html>   <!-- standards mode (not quirks mode) -->
<html lang="en">   <!-- lang aids screen readers, translation and SEO -->

<head>
    <meta charset="UTF-8">
    <meta
        name="viewport"
        content="width=device-width, initial-scale=1.0"
    >   <!-- makes the page responsive on mobile -->
    <title>My Website</title>
</head>

<body>
    <h1>Hello World</h1>
</body>

</html>
  • <!DOCTYPE html> tells the browser "this is an HTML5 document".
  • <html lang="en"> is the root element; lang defines the document language (lang="ar", lang="fr"…).
  • <head> contains information about the page — title, meta, link, style, script. It is not visible content.
  • <body> contains the visible page content.

Headings

Use <h1> through <h6> to describe content hierarchy.

<h1>Main Heading</h1>
<h2>Section</h2>
<h3>Subsection</h3>
<h4>...</h4>
<h5>...</h5>
<h6>...</h6>
Key point

<h1> should normally represent the main page/topic heading. Don't pick headings because of their size — CSS controls size, headings describe structure. Keep them in logical order.

Text & inline semantics

A paragraph uses <p>. Inline elements add meaning to words.

<p>This is a paragraph.</p>

<strong>Important</strong>
<em>Emphasis</em>
<mark>Highlighted</mark>
<small>Small text</small>
<del>Deleted</del>
<ins>Inserted</ins>
<sub>Subscript</sub>
<sup>Superscript</sup>

Use semantic elements when their meaning matters — a screen reader and a search engine both benefit from it.

Links

<a> (anchor) creates a hyperlink to another page, a file, or a spot on the same page; the destination lives in href. Use links to navigate — for actions like "save" or "delete", use a <button> instead.

<a href="https://example.com">Visit Website</a>

<!-- Open in a new tab -->
<a
    href="https://example.com"
    target="_blank"
    rel="noopener noreferrer"
>Visit Website</a>

<!-- Internal link -->
<a href="/about">About</a>

<!-- Same-page anchor: href matches an element's id -->
<a href="#contact">Contact</a>
<section id="contact"></section>
Note

rel="noopener noreferrer" is good practice whenever you use target="_blank".

Images

<img> embeds an image and is a void element — it has no closing tag. Always set alt: it is read aloud by screen readers, indexed by search engines, and shown if the image fails to load. Giving width/height reserves space and avoids layout shift.

<img
    src="flower.jpg"
    alt="Red flower"      <!-- describe the image; use alt="" if decorative -->
    width="500"
    height="300"
>

Important attributes: src, alt, width, height.

alt provides alternative text and matters for accessibility, SEO, and images that fail to load. For purely decorative images use an empty alt.

<img src="decoration.png" alt="">

Lists

Lists group related items and carry meaning for assistive tech. Use <ul> when order does not matter, <ol> for sequences or rankings, and <dl> for term/definition pairs.

<!-- Unordered -->
<ul>
    <li>Apple</li>
    <li>Banana</li>
    <li>Orange</li>
</ul>

<!-- Ordered -->
<ol>
    <li>Step One</li>
    <li>Step Two</li>
    <li>Step Three</li>
</ol>

<!-- Description list -->
<dl>
    <dt>HTML</dt>
    <dd>HyperText Markup Language</dd>
</dl>

Block, inline, div & span

<div> is a generic block container; <span> is a generic inline container. Use them only when no semantic element fits.

<div>Content</div>

<p>
    Hello
    <span class="highlight">world</span>
</p>
DisplayElementsBehavior
Blockdiv, p, h1, section, header, main, articleGenerally starts on a new line
Inlinespan, a, strong, em, imgStays within the current line

CSS can change display behavior (for example display: inline-block).

Void elements

Some elements have no closing tag: <img>, <input>, <br>, <hr>, <meta>, <link>. Don't write <img></img>.

Semantic elements

Prefer meaningful elements over a wall of <div>s.

ElementPurpose
<header>Introductory content, often navigation-related
<nav>Major navigation links
<main>Main page content (normally one per page)
<section>A thematic section, usually with a heading
<article>Independent content: blog post, news, forum post, product
<aside>Related content not essential to the main flow
<footer>Footer / closing content
 
<body>

    <header>          <!-- intro / navigation region -->
        <nav>        <!-- primary navigation links -->
            <a href="/">Home</a>
            <a href="/about">About</a>
            <a href="/contact">Contact</a>
        </nav>
    </header>

    <main>
        <section>
            <h2>Services</h2>
            <p>Our services...</p>
        </section>

        <section>
            <article>
                <h2>News Title</h2>
                <p>News content...</p>
            </article>
        </section>
    </main>

    <footer>
        <p>© 2026 My Website</p>
    </footer>

</body>

Buttons

<button> represents a clickable action and is natively focusable and keyboard-operable. The type matters inside a form: submit sends it, reset clears it, and button does nothing until you attach behavior.

<button type="button">Click Me</button>

<button type="submit">Submit</button>
<button type="reset">Reset</button>
Common mistake

Use <button> for actions. Don't use <div onclick="..."> for normal buttons — it breaks keyboard and screen-reader support.

GoalElementWhy
Navigate somewhere<a href>Right-click, open-in-new-tab, and SEO all work
Do an action<button>Focusable by default; announces as a button

Forms & labels

A <form> collects user input and submits it (as GET query params or a POST body). Every control should have a <label>: clicking the label focuses the field, and screen readers announce what the field is for.

<form>
    <label for="name">Name</label>
    <input id="name" name="name" type="text">

    <button type="submit">Submit</button>
</form>

The label's for value should match the input's id.

Attributes tune how an input behaves and validates. Prefer native attributes like required and pattern — the browser enforces them with no JavaScript — but always re-check the same rules on the server, since client-side validation can be bypassed.

Checkbox, radio, select, textarea, fieldset

Beyond text inputs, forms use checkboxes and radios for choices (radios sharing a name allow only one selection), <select> for dropdowns, <textarea> for multi-line text, and <fieldset>/<legend> to group related controls with a shared caption.

<!-- Checkbox -->
<label>
    <input type="checkbox" name="terms">
    Accept terms
</label>

<!-- Radio: same name groups options -->
<label>
    <input type="radio" name="gender" value="male">
    Male
</label>
<label>
    <input type="radio" name="gender" value="female">
    Female
</label>

<!-- Select -->
<select name="country">
    <option value="eg">Egypt</option>
    <option value="ae">UAE</option>
</select>

<!-- Textarea -->
<textarea name="message" rows="5" cols="30"></textarea>

<!-- Fieldset groups related controls -->
<fieldset>
    <legend>Personal Information</legend>
    ...
</fieldset>

Tables

Tables present tabular data — rows and columns of related values — never page layout. Structure them with <thead>, <tbody> and <th> so each header cell is programmatically tied to its column for screen readers.

<table>
    <thead>
        <tr>
            <th>Name</th>
            <th>Age</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <td>Ahmed</td>
            <td>30</td>
        </tr>
    </tbody>
</table>
table
  ↓
thead / tbody / tfoot
  ↓
tr
  ↓
th / td
Warning

Don't use tables to lay out a page. Use CSS Flexbox or Grid instead — see CSS → Flexbox and CSS → Grid.

Media: video, audio & iframe

<video> and <audio> embed playable media natively — no plugin needed — with controls rendering the play/pause UI. Nest <source> so the browser can fall back to another format. <iframe> embeds an entire external document such as a map or video player.

<video controls width="600">
    <source src="video.mp4" type="video/mp4">
</video>

<audio controls>
    <source src="audio.mp3" type="audio/mpeg">
</audio>

<iframe
    src="https://example.com"
    title="Example"
></iframe>

Useful video attributes: controls, autoplay, muted, loop, poster. <iframe> embeds external content.

Comments

Comments document your markup and are ignored by the browser. Use them to label regions or explain non-obvious nesting — but never leave secrets in them, because anyone can view the page source.

<!-- This is a comment. It is ignored by the browser. -->

Meta tags, title & SEO basics

The <head> describes the page to browsers and search engines. charset fixes text encoding, the viewport meta makes the page responsive, and title + description become the clickable snippet in search results.

<meta charset="UTF-8">

<meta
    name="viewport"
    content="width=device-width, initial-scale=1.0"
>

<meta
    name="description"
    content="My website description"
>

<title>My Website</title>
  • charset sets the character encoding.
  • The viewport meta is essential for responsive pages.
  • The description meta feeds search-engine previews.
  • <title> shows in the browser tab and search results, and is used for bookmarks.

For SEO, combine title, description, logical h1/h2 headings, semantic HTML, descriptive alt and href values, and meaningful button text.

Linking CSS & JavaScript

External files keep the three layers separate: content (HTML), style (CSS) and behavior (JS). <link> loads CSS in the head; <script> loads JS. Where you put the script affects speed and whether it can find elements already in the DOM.

<link rel="stylesheet" href="style.css">

<script src="script.js"></script>

<!-- Modern: defer parses HTML without blocking -->
<script src="script.js" defer></script>

HTML is structure, CSS is appearance, and JavaScript is behavior.

Warning

A plain <script> in the head blocks HTML parsing until it downloads and runs. Use defer (runs after parsing, order preserved) or put scripts at the end of <body>.

const button = document.getElementById("btn");

button.addEventListener("click", () => {
    alert("Clicked");
});

Global & data attributes

Global attributes apply to (almost) every element: id, class, style, title, hidden, lang, data-*.

<div id="card" class="product" data-id="123">
    ...
</div>

<!-- Custom data attributes -->
<div data-user-id="123" data-role="admin"></div>
element.dataset.userId; // "123"  (data-user-id becomes camelCase userId)

Accessibility & ARIA

  • Use semantic HTML.
  • Use labels for inputs.
  • Use alt text for meaningful images.
  • Use buttons for actions and links for navigation.
  • Use headings in logical order.
  • Don't rely on color alone.
  • Support keyboard navigation.

ARIA (Accessible Rich Internet Applications) adds semantics where native HTML is not enough.

<button aria-label="Close menu">×</button>
Warning

Don't use ARIA unnecessarily when native HTML already provides the correct meaning. Prefer semantic elements first.

HTML in React

React uses className instead of class, and htmlFor instead of for.

<!-- Traditional HTML -->
<button class="btn">Save</button>

<!-- React (JSX) -->
<button className="btn">Save</button>
function Form() {
    return (
        <form>
            <label htmlFor="email">Email</label>
            <input id="email" type="email" />
            <button type="submit">Submit</button>
        </form>
    );
}

Learn more on the React page.

HTML security basics

Don't blindly put user input into HTML. Be careful with innerHTML and, in React, dangerouslySetInnerHTML. Treat user input as text/data unless you have a trusted sanitization step.

Common mistake

Injecting raw user content with innerHTML is a common XSS vector. Server-side defenses are covered in Authentication & JWT.

HTML validation

Validate for: proper nesting, closing tags, unique IDs, valid attributes, and correct semantic elements.

<!-- Invalid: a block element inside a paragraph -->
<p>
    <div>Text</div>
</p>
Note

Use the W3C validator or your editor's HTML tooling to catch nesting and attribute errors early.

Quick recap

  • HTML = structure, content and meaning — CSS styles it, JS/React adds behavior.
  • Every page: doctype, html lang, head metadata, body content.
  • Choose elements for meaning, not size.
  • Semantic elements beat div soup.
  • Forms need labels; for matches input id.
  • alt text, logical headings and semantic HTML drive SEO and accessibility.
  • Escape reserved characters with entities; use data-* for custom data.
  • In React: className and htmlFor.
