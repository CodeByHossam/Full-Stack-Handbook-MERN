CSS

Cascading Style Sheets control layout, color, typography, spacing, responsive design and animation — and this page is the single source of truth for Flexbox, Grid and positioning.

Frontend Flexbox & Grid owner

Basic CSS syntax

A CSS rule has three parts: a selector (what to target), properties (what to change) and values. The browser reads top to bottom, so later rules can override earlier ones — this cascading behavior is the "C" in CSS.

selector {          /* selector: which elements to style */
    property: value;    /* property: value; */
}

p {                 /* element selector */
    color: blue;
    font-size: 18px;
}

Selector → p, property → color, value → blue.

Selectors

Selectors decide which elements a rule applies to. Start with the simplest one that works, then combine them (descendant, child, attribute) when you need precision. Prefer classes over IDs so overrides stay predictable.

SelectorExampleSelects

Class.card { }Elements with class="card"
ID#header { }The element with id="header"

Grouph1, h2, p { }Any matching selector
Descendant.card p { }p anywhere inside .card
Child.card > p { }Only direct children
Attributeinput[type="text"] { }Inputs with that attribute
Pseudo-classbutton:hover { }A state: :hover, :focus, :active, :visited, :first-child, :last-child, :nth-child()
Pseudo-element.title::before { }A part: ::before, ::after, ::first-letter, ::first-line

    border: 1px solid gray;
}

button:hover {
    background: blue;
}

.title::before {
    content: "★";
}

Colors

CSS offers several notations for the same result. Pick one and stay consistent: hex for exact brand values, rgb()/rgba() when you need an alpha channel, and hsl() when you want to tweak lightness or saturation by feel.

color: red;                    /* keyword  */
color: #ff0000;                /* hex      */
color: rgb(255, 0, 0);         /* rgb      */
color: rgba(0, 0, 0, 0.5);     /* rgba     */
color: hsl(0, 100%, 50%);      /* hsl      */

background-color: #ffffff;

CSS variables

Custom properties (CSS variables) store reusable values at the document level. Define them once on :root and reference them with var(), so re-theming a whole app means changing one value instead of hunting every usage.

:root {
    --primary: #2563eb;
    --secondary: #14b8a6;
    --text: #222;
}

button {
    background: var(--primary);
}

Custom properties keep a design system consistent and are extremely useful on professional projects.

Fonts & text

Typography rules control how text looks: family, size, weight and style. Set a base on body and let children inherit it, then layer alignment, line-height and letter-spacing only where needed.

body {
    font-family: Arial, sans-serif;
    font-size: 16px;
    font-weight: 400;
    font-style: normal;
}

/* Google Fonts */
@import url('https://fonts.googleapis.com/css2?family=Roboto:wght@300;400;700&display=swap');

body {
    font-family: 'Roboto', sans-serif;
}

Use the body element selector (not .body) unless your HTML actually has <body class="body">.

text-align: left | center | right;
text-decoration: none | underline;
text-transform: uppercase | lowercase | capitalize;
line-height: 1.6;
letter-spacing: 1px;

The box model

Every element is a content box wrapped in padding, a border, and margin.

┌───────────────────────────┐
│          MARGIN           │
│   ┌───────────────────┐   │
│   │      BORDER       │   │
│   │  ┌─────────────┐  │   │
│   │  │   PADDING   │  │   │
│   │  │ ┌─────────┐ │  │   │
│   │  │ │ CONTENT │ │  │   │
│   │  │ └─────────┘ │  │   │
│   │  └─────────────┘  │   │
│   └───────────────────┘   │
└───────────────────────────┘

Content → Padding → Border → Margin
* {
    box-sizing: border-box;
}
Key point

border-box makes width/height include padding and border, so size calculations are far easier. Almost every project sets it globally.

Width & height

Explicit width/height set an element's size; max-/min- constraints let it flex between bounds. Relative units make blocks responsive to their parent or the viewport instead of fixed pixels.

width: 300px;
height: 200px;

max-width: 1200px;
min-height: 100vh;

width: 50%;      /* percentage of parent */
width: 100vw;    /* viewport width       */
height: 100vh;   /* viewport height      */

Margin & padding

Margin is space outside an element's border (between siblings); padding is space inside, between the border and the content. Shorthands take 1, 2, or 4 values, read clockwise from the top.

margin: 20px;                    /* all sides */
margin: 10px 20px;               /* T/B = 10, L/R = 20 */
margin: 10px 20px 30px 40px;     /* Top Right Bottom Left */

padding: 20px;
padding: 10px 20px;
padding: 10px 20px 30px 40px;    /* TRBL */

Center a block horizontally with auto margins:

.container {
    max-width: 1200px;
    margin: 0 auto;
}

Borders, radius & shadow

Borders draw a line around the box, border-radius rounds its corners, and box-shadow adds depth. Borders take part in layout (they add to the box size under the default content-box); radius and shadow are pure visual polish.

border: 1px solid black;

border-top: 2px dashed red;
border-right: 1px solid #ccc;
border-bottom: none;
border-left: 1px solid #ccc;
border-color: gray;

border-radius: 10px;
border-radius: 50%;    /* circle */

box-shadow: 0 4px 10px rgba(0, 0, 0, 0.15);

Box-shadow structure: x y blur color.

Display

The display property defines how an element participates in layout: as a block (own line), inline (inside text flow), a flex/grid container, or removed from the flow entirely with none.

display: block;
display: inline;
display: inline-block;
display: none;
display: flex;
display: grid;

See the HTML block vs inline table for the defaults of common elements.

Flexbox (owner)

Flexbox lays out items along one axis (a row or a column). Put display: flex on the container; its direct children become flex items.

PropertyApplied toCommon values
displayContainerflex
flex-directionContainerrow, column
justify-contentContainer (main axis)flex-start, center, flex-end, space-between, space-around, space-evenly
align-itemsContainer (cross axis)flex-start, center, flex-end, stretch
flex-wrapContainernowrap, wrap

.container {
    display: flex;
    flex-direction: row;      /* or column */
    justify-content: center;  /* main axis  */
    align-items: center;      /* cross axis */
    gap: 20px;
    flex-wrap: wrap;          /* responsive */
}

.item {
    flex: 1;                  /* share available space */
}
Note

Tailwind and React Native both link here for Flexbox concepts — the properties are the same, only the syntax differs.

CSS Grid (owner)

Grid lays out items in rows and columns at the same time. Reach for Grid when the track structure is known up front (a dashboard, a gallery, a page shell); use Flexbox when content should decide the sizes along a single axis.

FlexboxGrid
AxesOne (row or column)Two (rows and columns)
ThinkingContent-driven sizingLayout-driven tracks
Best forNavbars, toolbars, centering, distributing itemsPage shells, galleries, dashboards
Wrappingflex-wraprepeat(auto-fit, …)
 
.container {
    display: grid;
    grid-template-columns: repeat(3, 1fr);  /* 3 equal-width tracks */
    gap: 20px;                              /* space between cells  */
}
┌────┐ ┌────┐ ┌────┐
│    │ │    │ │    │
└────┘ └────┘ └────┘

A responsive grid that adjusts the number of columns automatically:

grid-template-columns: repeat(auto-fit, minmax(250px, 1fr));
Key point

repeat(auto-fit, minmax(...)) is the go-to pattern for card galleries that reflow without a single media query.

Positioning (owner)

The position property takes an element out of (or keeps it in) normal flow and lets you offset it. The key gotcha: absolute is positioned relative to the nearest ancestor that is itself positioned — usually you set position: relative on the parent.

ValueBehavior
staticDefault normal flow
relativeOffset from its normal position; establishes a containing block for absolute children
absolutePositioned relative to the nearest positioned ancestor
fixedPositioned relative to the viewport; stays while scrolling
stickyActs relative until a threshold, then sticks
 
.parent { position: relative; }

.child {
    position: absolute;
    top: 0;
    right: 0;
}

.navbar { position: fixed; top: 0; left: 0; width: 100%; }

.sticky-header { position: sticky; top: 0; }

z-index

z-index controls stacking order when boxes overlap: higher numbers paint on top. It only has an effect on positioned elements (or flex/grid items), so a z-index on a static element does nothing.

.modal {
    position: fixed;   /* positioned, so z-index applies */
    z-index: 1000;
}

A higher z-index generally appears above lower layers. It only applies to positioned (or flex/grid) elements.

Watch out

z-index can't escape its stacking context. A parent with transform, opacity < 1, or its own z-index creates a new context, so its children can never rise above elements in a sibling context — no matter how high the number.

Overflow

overflow decides what happens when content is bigger than its box: clip it (hidden), scroll it (auto/scroll), or let it spill out (the default, visible). Use the axis-specific properties to control each direction separately.

overflow: hidden | auto | scroll;
overflow-x: auto;
overflow-y: auto;

Transitions

A transition animates a property smoothly between two states, usually triggered by :hover or :focus. You declare which properties animate and how long; the browser generates the in-between frames. Keep it to cheap properties like transform and opacity.

button {
    transition:
        background-color 0.3s ease,   /* list each property to animate */
        transform 0.3s ease;
}

button:hover {
    transform: scale(1.05);
}

Transforms

transform moves, scales, rotates or skews an element without affecting the layout of siblings — the other boxes stay exactly where they were. It is GPU-accelerated, so it is the performant way to animate movement and scale.

transform: translateX(100px);
transform: translateY(50px);
transform: scale(1.2);
transform: rotate(45deg);
transform: skew(10deg);

/* Combine multiple transforms */
transform: translateX(100px) rotate(20deg) scale(1.1);

Keyframe animations

@keyframes defines a multi-step animation, then the animation shorthand plays it. Unlike a transition (two states plus a trigger), a keyframe animation can loop, run automatically on load, and pass through several stages.

@keyframes fadeIn {
    from { opacity: 0; }
    to   { opacity: 1; }
}

.box { animation: fadeIn 1s ease; }

@keyframes move {
    0%   { transform: translateX(0); }
    50%  { transform: translateX(200px); }
    100% { transform: translateX(0); }
}

.box { animation: move 2s infinite; }   /* name | duration | iteration */

Media queries & mobile-first

Media queries apply CSS only when a condition matches — typically screen width, but also orientation or print. They are how one stylesheet adapts to phones, tablets and desktops without separate pages.

@media (max-width: 768px) {   /* max-width: desktop-first */
    .container {
        flex-direction: column;
    }
}

Mobile-first flips this around: write the small-screen layout as the base, then add min-width queries for larger screens.

.container {
    display: flex;
    flex-direction: column;
}

@media (min-width: 768px) {
    .container {
        flex-direction: row;
    }
}

clamp(), calc() & units

clamp() scales a value between a minimum and a maximum with no media query, and calc() does math while mixing units. Relative units keep a design proportional to screen size and to the user's font settings.

font-size: clamp(1.5rem, 4vw, 4rem);
/*          minimum   flexible   maximum */

width: calc(100% - 40px);

CSS reset

Browsers ship with their own default margins, paddings and font sizes, which differ slightly between engines. A reset normalizes those starting points so your layout behaves predictably everywhere.

* {          /* every element */
    margin: 0;
    padding: 0;
    box-sizing: border-box;  /* width includes padding + border */
}

Forms & buttons

Form controls need explicit styling because each browser renders them differently by default. A consistent input style (full width, padding, border, radius) plus a visible focus state and a button hover gives an interface a professional feel.

input {
    width: 100%;
    padding: 12px;
    border: 1px solid #ccc;
    border-radius: 8px;
}

input:focus {
    outline: none;
    border-color: blue;
}

button {
    padding: 12px 20px;
    border: none;
    border-radius: 8px;
    background: #4f46e5;
    color: white;
    cursor: pointer;
}

button:hover { background: #4338ca; }

Specificity

Specificity is the scoring system browsers use to decide which conflicting rule wins. The more specific the selector, the higher it scores — which is why one ID can beat many classes.

Inline  (highest)
   ↓
ID
   ↓
Class
   ↓
Element (lowest)

An ID beats a class, a class beats an element. Avoid styling by ID — prefer classes so overrides stay predictable.

Common mistake

Reaching for !important to win a specificity fight usually hides the real problem. Fix the selector instead; reserve !important for genuinely exceptional overrides.

Inheritance

Some properties (mostly text: color, font-family, line-height) flow from a parent to its children automatically; others (margin, border, background) do not. Knowing which is which explains many "why didn't my style apply?" surprises.

body {
    color: #222;
    font-family: Arial;
}

Most children inherit text properties (color, font) unless a rule overrides them.

Combining classes, nesting & file structure

Real stylesheets are organized, not one giant file. Combine classes for variants, keep selectors shallow, group files by concern, and split components into their own files so the project stays maintainable as it grows.

.card { padding: 20px; }
.card.active { border: 2px solid blue; }
<div class="card active"></div>

Modern CSS also supports nesting, but understand normal CSS first.

.card {
    padding: 20px;

    .title {
        font-size: 24px;
    }
}

For larger projects, organize styles logically:

styles/
    reset.css
    variables.css
    global.css
    components/
        button.css
        card.css
        navbar.css

BEM naming

BEM = Block Element Modifier. It keeps class names predictable in large projects.

.card            /* block   */
.card__title     /* element */
.card__image     /* element */
.card--featured  /* modifier */
<div class="card card--featured">
    <h2 class="card__title"></h2>
</div>

CSS & React (CSS Modules)

CSS Modules give every class a unique generated name at build time, so class names are scoped to the file that imports them. This removes the "two components both happened to use .button" collision.

import "./Button.css";

function Button() {
    return <button className="button">Save</button>;
}

CSS Modules avoid class-name conflicts by scoping names per file.

import styles from "./Button.module.css";

<button className={styles.button}>
    Save
</button>

Where CSS fits

Plain CSS, a utility framework and a JS animation library solve different problems and are often used together: CSS for the design system and custom work, Tailwind for speed, GSAP for complex motion.

ToolBest for
Plain CSSUnderstanding CSS, custom designs, complex styles and CSS architecture
TailwindFast development, React apps, consistent utilities, rapid UI building
GSAPComplex animation, timelines, ScrollTrigger, advanced sequences
 
/* CSS: simple hover effect */
button:hover { transform: scale(1.05); }
// GSAP: scripted animation
gsap.to(button, { scale: 1.2, duration: 1 });

Learn both plain CSS and a utility framework — they solve different problems.

Debugging CSS

When CSS "doesn't work", work through this list in Chrome DevTools:

  • Inspect the element.
  • Check computed styles.
  • Check whether the selector matches.
  • Check specificity.
  • Check the parent layout.
  • Check width / height.
  • Check position.
  • Check overflow.
  • Check z-index.
  • Check media queries.

Quick recap

  • Target elements with selectors; understand specificity and inheritance.
  • Everything is the box model — set box-sizing: border-box.
  • Flexbox = one axis; Grid = two axes. This page owns both.
  • position + z-index + overflow control layering and clipping.
  • Transitions and keyframes animate; transforms are GPU-friendly.
  • Build mobile-first with min-width media queries.
  • Use rem, clamp() and calc() for scalable, responsive sizing.
  • Organize with variables, BEM and CSS Modules; debug in DevTools.
