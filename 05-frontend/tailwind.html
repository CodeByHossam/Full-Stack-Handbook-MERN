Tailwind CSS

A utility-first CSS framework: instead of writing custom CSS rules, you compose small utility classes directly in your markup.

Frontend Utility-first

Installation & setup

Tailwind is a utility-first framework: instead of writing a custom class per component, you compose small single-purpose classes directly in the markup. Styling therefore lives next to the element and you skip the "invent a class name, then hunt for it in a huge stylesheet" cycle.

npm install tailwindcss @tailwindcss/vite

Then configure Tailwind according to your Tailwind version (for Vite, the plugin is added to vite.config.js). In React, Tailwind classes are written as a className string.

Custom CSSUtility-first (Tailwind)
Where styles liveSeparate .css filesIn the markup, as classes
NamingYou invent class namesComposable, predictable utilities
GrowthRisk of unused or conflicting rulesUnused utilities are purged at build
Best forComplex custom designs, design systemsFast, consistent UI in React apps
 
<div className="p-5 bg-white rounded-xl"></div>
Warning

Tailwind uses className in React but class in normal HTML. Mixing them up is a common beginner error.

Spacing

Spacing utilities map to one consistent scale, so a gap of "6" is the same everywhere. p-* sets padding and m-* sets margin; add an axis (x/y) or a side (t/r/b/l) to target one direction.

<div className="p-6 mt-4"></div>
<!-- p-6 = padding on all sides; mt-4 = margin-top only -->
PrefixApplies to
p-padding (all sides)

m-margin (all sides)

The spacing scale is consistent: p-1 p-2 p-3 p-4 p-5 p-6 p-8 p-10 p-12 p-16 p-20 p-24. The most common spacing values in practice are p-4, p-6 and p-8.

Width & height

Size utilities set width and height. Fractional widths (w-1/2) split the parent, w-full fills it, and max-w-* caps a container so lines of text stay readable instead of stretching across a wide screen.

<div className="w-full"></div>
<section className="min-h-screen"></section>

Colors & shades

Color utilities follow {property}-{color}-{shade}: the prefix (text-, bg-, border-) chooses what is colored, and the shade (50–900) chooses how light or dark.

<h1 className="text-white">Hello</h1>   <!-- text- prefix sets the color -->
TypeExamples
Texttext-white, text-black, text-gray-500, text-blue-500, text-red-500, text-green-500
Backgroundbg-white, bg-black, bg-gray-100, bg-blue-500, bg-indigo-600

Each color has shades from 50 to 900. Think of 500 as the middle, 600/700 as darker, and 100/200 as lighter.

bg-blue-50 bg-blue-100 bg-blue-200 bg-blue-300 bg-blue-400
bg-blue-500 bg-blue-600 bg-blue-700 bg-blue-800 bg-blue-900

Typography

Typography utilities adjust font size, weight, alignment and spacing. Size (text-*), weight (font-*) and alignment usually get you most of the way; line-height and tracking fine-tune readability.

<h1 className="text-4xl font-bold text-center">Welcome</h1>
<p className="leading-relaxed tracking-wide">Some text...</p>

Responsive prefixes (mobile-first)

Responsive prefixes apply a utility only from a breakpoint upward. Because Tailwind is mobile-first, the unprefixed class is the small-screen default and md:, lg: layer changes in at larger screens.

<h1 className="text-2xl md:text-4xl lg:text-6xl"></h1>
<!-- 2xl on phones · 4xl from md · 6xl from lg -->

Tailwind is mobile-first. Base classes apply to all screens; prefixed classes apply from that breakpoint upward: sm:, md:, lg:, xl:.

Common mistake

Write text-xl md:text-3xl lg:text-5xl, not lg:text-xl md:text-3xl text-5xl. Always go mobile → tablet → desktop.

<div className="grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-6"></div>

Dark mode

The dark: prefix applies a utility only when dark mode is active, so you can supply both light and dark values on the same element — no separate stylesheet or duplicated markup.

<div className="bg-white text-black dark:bg-gray-900 dark:text-white"></div>
<!-- light: white bg, black text · dark: gray-900 bg, white text -->

The dark: prefix applies a utility only when dark mode is active.

Borders, radius, shadow & opacity

These utilities style a box's edges and depth: border width and color, corner radius, shadow, and opacity. Each maps directly to the CSS property of the same name.

<div className="border border-gray-200 rounded-xl shadow-lg opacity-100"></div>

Interactive states: hover, focus, active

State variants apply a utility only in a given interaction state. They are how you add hover, focus and press feedback with no custom CSS — so buttons and inputs feel responsive to the user.

<button className="bg-blue-600 hover:bg-blue-700"></button>

<input className="border focus:ring-2 focus:ring-blue-500">

<button className="active:scale-95"></button>
  • hover: — only while hovering.
  • focus: — while focused (keyboard users rely on this).
  • active: — while pressed; great for click feedback.

Transitions & transforms

Transition utilities control which properties animate and for how long; transform utilities change position, scale and rotation. Pair them so a hover state eases in smoothly instead of snapping.

<button className="bg-blue-500 hover:bg-blue-700 transition-colors duration-300"></button>
<!-- animate only colors, over 300ms -->

<div className="hover:scale-105 transition-transform"></div>

Conditional classes in React

In React className is just a string, so you can build it dynamically with a template literal or a conditional expression — toggling a state-driven class for active/inactive looks.

const isActive = true;

// base classes + a color that depends on state
<button className={`px-4 py-2 ${isActive ? "bg-blue-600" : "bg-gray-400"}`}>
    Button
</button>

For larger projects use clsx (or classnames):

import clsx from "clsx";

<button
    className={clsx(
        "px-4 py-2 rounded",
        isActive ? "bg-blue-600" : "bg-gray-400"
    )}
>
    Button
</button>

Arbitrary values

Square brackets let you use any value that is not on the default scale — w-[350px], bg-[#123456], top-[120px]. It is an escape hatch for one-off needs, not a habit.

<div className="w-[350px] top-[120px] bg-[#123456] text-[22px]"></div>
Warning

Arbitrary values escape the design system. Use them sparingly when the standard scale genuinely isn't enough.

Custom colors & design system

For a professional project, define and reuse a small palette and a consistent set of tokens.

TokenExample choice
Primaryindigo
Secondaryteal
Neutralgray

Standardize colors, spacing, font sizes, border radius, shadows, and the recipes for buttons, inputs and cards. A primary button should always be, for example, bg-indigo-600 hover:bg-indigo-700.

Reuse components, not class strings

Instead of repeating the same long utility list everywhere, wrap it in a component and reuse it.

<Button>Save</Button>
<Button>Delete</Button>
Common mistake

Don't make huge className strings that repeat across the app. If you type the same utilities three times, extract a component. Also avoid too many arbitrary values, inconsistent colors, !important, and mixing several styling systems at once.

Tailwind and GSAP complement each other: Tailwind controls the design (layout, colors, spacing), GSAP controls complex animation. See GSAP.

Accessibility

Don't use Tailwind instead of semantic HTML.

<!-- Good -->
<button>Save</button>

<!-- Bad -->
<div className="cursor-pointer">Save</div>

Also consider focus states, color contrast, keyboard navigation and screen readers. The base elements are covered in HTML → Accessibility & ARIA.

Quick recap

  • Tailwind is utility-first: compose small classes in the markup.
  • className in React, class in HTML.
  • Learn the pattern (property + value), not every class.
  • Mobile-first: base, then sm: md: lg: xl:.
  • States use hover: focus: active:; dark mode uses dark:.
  • Flexbox/Grid concepts live in CSS; Tailwind just names them.
  • Use a small design system and reuse components — never vast repeated className strings.
  • Keep semantic HTML and accessible focus states.
