TypeScript

JavaScript plus static types: catch errors before you run the code and type every layer of a MERN app from React props to Express controllers and Mongoose models.

TypeScript Types & Generics Full-stack typing

What is TypeScript?

TypeScript is JavaScript with static types. You annotate values, and the compiler checks them and catches mistakes before the code runs.

// JavaScript
let age = 30;

// TypeScript
let age: number = 30;
Key point

Types are erased at compile time — the browser still runs plain JavaScript. TypeScript only helps you (and your editor) catch problems during development.

Basic types

These are the primitive building blocks — string, number, and boolean — plus arrays. Annotating them makes intent explicit and lets the compiler reject a wrong assignment.

let name: string = "Alice";    // text
let age: number = 42;          // any number: integer or decimal
let isAdmin: boolean = false;  // true or false

let fruits: string[] = ["apple", "banana", "orange"];  // array of strings
let numbers: number[] = [10, 20, 30];                  // array of numbers

The compiler also infers types from the assigned value, so annotations are often optional when the type is obvious.

any — avoid it

any disables type checking for a value. It should be a last resort.

let value: any = "hello";
value = 100;    // allowed - any turns off checking
value = true;   // allowed - every value fits "any"
Common mistake

Reaching for any everywhere defeats the purpose of TypeScript. Prefer a specific type, a union, unknown, or a generic. Use unknown when a value's type is genuinely not known yet, then narrow it.

// Avoid
let user: any;    // no autocomplete, no error on typos

// Better
let user: User;   // compiler enforces the expected shape

Union and literal types

A union lets a value be one of several types.

let id: string | number;  // value may be either type

id = 123;      // ok
id = "ABC123"; // ok too

A literal type restricts a value to exact allowed strings (or numbers/booleans). It is perfect for statuses and roles.

let role: "admin" | "user" | "manager";  // only these exact strings compile

role = "admin";       // ok

// role = "student";  // Error - not one of the allowed literals

Object types

Describe the shape of an object inline, or name the shape with an interface or a type.

let user: {
    name: string;
    age: number;
    isAdmin: boolean;
} = {
    name: "Alice",
    age: 42,
    isAdmin: false
};

Interface vs type

Both describe objects. A ? after a property name marks it optional.

interface User {
    id: string;
    name: string;
    email: string;
    age?: number;   // optional
}

const user1: User = {
    id: "123",
    name: "Alice",
    email: "test@email.com"
};
type Product = {
    id: string;
    name: string;
    price: number;
};

const product: Product = {
    id: "1",
    name: "Laptop",
    price: 1000
};

Describes objectsYesYes

Key point

For most React projects either is fine. Use interface for object contracts and public APIs, and type for unions, aliases and utility-type compositions.

Functions: parameters, return and void

Type the parameters and the return value.

function add(a: number, b: number): number {  // (params): returnType
    return a + b;
}

const multiply = (a: number, b: number): number => {
    return a * b;
};

void means the function returns nothing useful.

function sayHello(name: string): void {
    console.log(`Hello ${name}`);
}

Optional parameters use ?; default parameters supply a fallback value.

function greet(name: string, age?: number) {
    console.log(name);
}

greet("Alice");
greet("Alice", 42);

function welcome(name: string = "Guest") {
    console.log(name);
}
Note

Optional parameters must come after required ones. A parameter with a default value is also treated as optional at the call site.

null and undefined

A typed variable cannot normally hold nothing. When a value may genuinely be absent, add null or undefined to its union so the compiler forces you to handle the empty case.

let username: string | null = null;  // explicitly allowed to be empty

username = "Alice";                  // now a real string

With strict mode enabled, null and undefined must be part of the type before you can assign them.

Arrays of objects

Type an array with Type[]. Every element is then checked against that shape, and array methods such as filter keep the element type on the result.

interface Product {
    id: string;
    name: string;
    price: number;
}

const products: Product[] = [
    { id: "1", name: "Laptop", price: 1000 },
    { id: "2", name: "Phone", price: 500 }
];

function getExpensiveProducts(products: Product[]): Product[] {
    return products.filter(product => product.price > 800);  // returns Product[]
}

Enums

An enum gives a set of named constants. String enums are usually the safest choice.

enum Role {
    USER = "user",
    ADMIN = "admin",
    MANAGER = "manager"
}

const userRole: Role = Role.ADMIN;
Note

A union of string literals (type Status = "loading" | "success" | "error") is often preferred over an enum in modern TypeScript, because it is lighter and simpler at runtime.

Type alias with union

A type alias gives a name to a union so you can reuse it everywhere. This is the idiomatic way to model a value that may only be one of a few known strings.

type Status = "loading" | "success" | "error";

let status: Status = "loading";  // only the three listed strings compile

Generics

Generics let you write reusable code that keeps its type. T is a placeholder that becomes concrete at the call site.

function getFirst<T>(array: T[]): T {
    return array[0];
}

const firstNumber = getFirst([1, 2, 3]);       // number
const firstName = getFirst(["John", "Mike"]);  // string

Interfaces can be generic too — very handy for wrapping API responses.

interface ApiResponse<T> {
    success: boolean;
    data: T;
}

const response: ApiResponse<Product[]> = {
    success: true,
    data: products
};

Async functions and Promise

Promise<T> says a value will be available later, of type T.

async function getUser(): Promise<User> {
    const response = await fetch("/api/user");
    return response.json();
}

function fetchUser(): Promise<User> {
    return fetch("/api/user").then(res => res.json());
}
Warning

response.json() returns Promise<any> at the type level. In real code, validate the payload (for example with Zod) before trusting it as User.

Type assertion and DOM elements

An assertion tells TypeScript "I know this value's type" — use it when you have information the compiler does not.

const input = document.getElementById("name") as HTMLInputElement;
console.log(input.value);

const button = document.getElementById("button") as HTMLButtonElement;

button.addEventListener("click", () => {
    console.log("Clicked");
});
Common mistake

Assertions do not convert anything at runtime — they only silence the compiler. Asserting the wrong type moves the bug to runtime.

Optional chaining and nullish coalescing

?. short-circuits safely when a value is null or undefined.

user1.age?.toString();

const displayName = user1.name ?? "Guest";
Note

?? only falls back on null/undefined, unlike || which also falls back on 0, "" and false.

readonly

Mark a property as readonly to prevent reassignment after creation.

interface User {
    readonly id: string;
    name: string;
}

// user1.id = "456"; // Error

Function types

Type a variable or parameter that holds a function.

type Calculator = (a: number, b: number) => number;

const addNumbers: Calculator = (a, b) => {
    return a + b;
};

Utility types: Record, Pick, Omit, Partial

These built-in helpers build new types from existing ones.

UtilityResult
Record<K, V>An object with keys of type K and values of type V
Pick<T, K>A type with only the listed properties
Omit<T, K>A type with the listed properties removed
Partial<T>A type where all properties become optional
 
const users: Record<string, User> = {};

type UserPreview = Pick<User, "id" | "name">;

type UserWithoutId = Omit<User, "id">;

type UpdateUser = Partial<User>;   // great for PATCH bodies

Typing React

Type props with an interface. See React for the components themselves.

interface ButtonProps {
    text: string;
    disabled?: boolean;
    onClick: () => void;
}

function Button({ text, disabled, onClick }: ButtonProps) {
    return (
        <button disabled={disabled} onClick={onClick}>
            {text}
        </button>
    );
}

State is generic: pass the type in the angle brackets. Use a union with null for values that start empty.

import { useState } from "react";

const [count, setCount] = useState<number>(0);        // number state
const [user, setUser] = useState<User | null>(null);  // starts empty, filled later

Events come with precise types such as ChangeEvent<HTMLInputElement>.

import { ChangeEvent } from "react";

const handleChange = (e: ChangeEvent<HTMLInputElement>) => {
    console.log(e.target.value);
};

Controlled form state with a dedicated interface:

interface FormData {
    name: string;
    email: string;
}

const [form, setForm] = useState<FormData>({ name: "", email: "" });

Typing API data

Model the resource once, then reuse it for fetch functions.

interface Product {
    _id: string;
    name: string;
    price: number;
}

async function getProducts(): Promise<Product[]> {
    const response = await fetch("/api/products");
    return response.json();
}

TypeScript + Express

Type the three core arguments: req, res, next. See Express for routing and middleware.

import { Request, Response, NextFunction } from "express";

const getUsers = async (
    req: Request,
    res: Response,
    next: NextFunction
) => {
    try {
        // ...
    } catch (error) {
        next(error);  // hand the error to Express error middleware
    }
};
Note

You can make the request more precise with generics: Request<Params, ResBody, ReqBody, Query>, for example Request<{}, {}, { name: string }>.

TypeScript + Mongoose

Describe the document with an interface that extends Document, then pass it to Schema and model. See MongoDB Basics for schemas and CRUD.

import { Schema, model, Document } from "mongoose";

interface IUser extends Document {
    name: string;
    email: string;
    password: string;
}

const userSchema = new Schema<IUser>({
    name: { type: String, required: true },
    email: { type: String, required: true },
    password: { type: String, required: true }
});

const UserModel = model<IUser>("User", userSchema);  // typed model: queries return IUser

Compiler and tsconfig

TypeScript ships a compiler, tsc. Install it as a dev dependency, generate a tsconfig.json, and run it to type-check your files and emit plain JavaScript. In a MERN app a bundler (Vite) or ts-node usually drives the compiler for you.

npm install -D typescript

# create a config file
npx tsc --init

# compile once
npx tsc

# compile on change
npx tsc --watch

A minimal, sensible tsconfig.json for a Node/React project:

{
    "compilerOptions": {
        "target": "ES2020",              // JavaScript version to emit
        "module": "ESNext",              // import/export syntax to use
        "moduleResolution": "bundler",
        "strict": true,                  // turn on all safety checks
        "esModuleInterop": true,         // import CommonJS packages cleanly
        "skipLibCheck": true,            // skip node_modules - faster builds
        "forceConsistentCasingInFileNames": true,
        "jsx": "react-jsx",              // compile JSX for React
        "outDir": "dist"                 // where compiled JS goes
    },
    "include": ["src"]                   // only type-check the src folder
}
Key point

Keep "strict": true. It turns on strictNullChecks and other safety checks — the main reason to use TypeScript in the first place.

File extensions

Pick the extension by what the file contains. JSX syntax is only allowed in .jsx and .tsx, and TypeScript only type-checks .ts / .tsx.

ExtensionContents
.jsJavaScript
.jsxJavaScript + JSX
.tsTypeScript
.tsxTypeScript + JSX (React components)

JavaScript vs TypeScript

The same object, first without types then with them:

// JavaScript
const user = {
    name: "Alice",
    age: 42
};
// TypeScript
interface User {
    name: string;
    age: number;
}

const user: User = {
    name: "Alice",
    age: 42
};
Note

TypeScript is a superset of JavaScript: every valid JS file is (almost always) valid TS. You can adopt it gradually by renaming files and adding types where they matter most.

Quick recap

  • TypeScript = JavaScript + static types, checked before runtime
  • Core types: string, number, boolean, arrays, objects; avoid any
  • Unions and literal types model "one of these values"
  • interface for object contracts, type for unions and aliases; both describe objects
  • Type function params and return values; use void, ? and defaults
  • Generics (function getFirst<T>, ApiResponse<T>) keep reusable code type-safe
  • Promise<T> types async results; assertions, ?., ?? and readonly add safety
  • Utility types: Record, Pick, Omit, Partial
  • Type React props, state, events and forms; model API data once and reuse it
  • Type Express with Request/Response/NextFunction; Mongoose with IUser extends Document
  • Compile with tsc, keep strict: true, and use .ts / .tsx
