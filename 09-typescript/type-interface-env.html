TypeScript Deep Dive

Types vs. Interfaces, Vite Env, and Express Env

1. The Core: type vs interface

For 90% of everyday use cases, they are identical. You can use either to describe the shape of an object.

Feature interface type
Declaration Merging
(Combining types with the same name)		 YES NO (Throws error)
Unions, Tuples, Primitives
(e.g., string | number)		 NO YES
Extending Uses extends Uses & (Intersection)

Why do we care about Declaration Merging?

It is the only reason to use interface. If you re-declare an interface with the same name, TypeScript combines them. If you do that with type, TypeScript crashes with a "Duplicate identifier" error.

interface Box { width: number }
interface Box { height: number } 
// Box is now { width: number; height: number }

Why type feels easier:

  • One keyword for everything (objects, unions, tuples, primitives).
  • No deciding "is this an interface or a type?"
  • Composition with & feels natural.

The Golden Rule: Use type by default for everything you own. Only use interface when you are augmenting (merging into) existing library or global types.

2. Vite Env (Frontend)

Vite replaces import.meta.env.VITE_* with actual strings at build time. But TypeScript has zero access to your .env file. It doesn't know these variables exist.

The Vite Declaration File

/// <reference types="vite/client" />

interface ImportMetaEnv {
  readonly VITE_SITE_URL: string;
  readonly VITE_FORM_PROVIDER: string;
}

interface ImportMeta {
  readonly env: ImportMetaEnv;
}

How it works (Line by Line)

  • /// <reference types="vite/client" />: This is a Triple-Slash Directive. It tells TypeScript to load Vite's built-in type definitions from node_modules before reading this file. Vite already declares an empty ImportMetaEnv and an ImportMeta interface.
  • interface ImportMetaEnv: Because Vite already declared this interface, our declaration merges with it. We are adding our custom keys (VITE_SITE_URL, etc.) to Vite's empty interface.
  • interface ImportMeta: This is the bridge. import.meta is a real object. We are telling TypeScript: "Hey, the env property on import.meta has the type ImportMetaEnv."

Why can't I just use an inline type inside ImportMeta?

You can write interface ImportMeta { readonly env: { VITE_SITE_URL: string } }. It compiles. But it creates an isolated, anonymous type. By using a named ImportMetaEnv interface, you allow other files to merge into it, reference it, and use it. It connects your type to the rest of the ecosystem.

Why can't I use type here?

If you write type ImportMetaEnv = { ... }, TypeScript will throw a Duplicate identifier error because Vite already declared it as an interface. type replaces; interface merges.

3. Express Env (Backend)

Node.js has process.env. TypeScript knows it exists (thanks to @types/node), but it only knows it as string | undefined. It doesn't know your specific keys.

The Express Declaration File

namespace NodeJS {
  interface ProcessEnv {
    DATABASE_URL: string;
    PORT: string;
  }
}

How it works

  • namespace NodeJS: In Node's type definitions, all global Node types are grouped inside a namespace called NodeJS. This is just a folder. We are opening that folder.
  • interface ProcessEnv: Inside that folder, there is an interface called ProcessEnv. Because we are using interface, we are merging our keys into it.
  • Why no /// reference?: Node.js types are global. They are loaded automatically by your tsconfig.json (via "types": ["node"]), so you don't need a reference directive.

The difference from Vite

Vite uses import.meta.env (a custom object). Node uses process.env (a global object). Vite requires an explicit reference directive. Node does not.

4. The "Why it works" Magic

TypeScript checks your code at compile time (in your editor). Vite/Node handle the values at runtime.

In Development (Vite):

  • You write: const url = import.meta.env.VITE_SITE_URL;
  • Vite reads your .env file.
  • Vite replaces your code in memory with: const url = "https://creaova.ae";
  • The browser receives the hardcoded string.

TypeScript's job is just to ensure you don't make typos while typing VITE_SITE_URL. The actual value comes from Vite's bundling process.

In Express (Node):

You need a library like dotenv to read the .env file and inject the values into process.env. Then, at runtime, process.env.DATABASE_URL is a real string.
