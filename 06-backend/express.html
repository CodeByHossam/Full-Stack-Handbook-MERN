What Express does

Express is a Node.js web framework that turns raw HTTP handling into clean routes and middleware. A request travels like this:

Create an Express server

express() creates the application object; app.listen() binds it to a port and starts accepting requests. This is the entry point of every MERN backend (server.js).

const express = require("express");

const app = express();   // the application: routes + middleware attach to it

const PORT = 5000;       // often process.env.PORT in real apps

app.listen(PORT, () => {
    console.log(`Server running on port ${PORT}`);  // server is now live
});

Middleware

Middleware functions run in order on every request and receive (req, res, next). They are how you parse bodies, log, authenticate, and pre-process a request before it reaches a route — Express is essentially a chain of these functions.

// read JSON from the request body into req.body
app.use(express.json());

// read URL-encoded form data (HTML form posts)
app.use(express.urlencoded({ extended: true }));

// custom middleware — runs for every request that follows it
app.use((req, res, next) => {
    console.log(req.method, req.url);   // e.g. GET /api/users
    next();                             // without this the request hangs
});
Key point

Call next() to pass control to the following middleware. Forgetting it makes the request hang.

Basic route

app.get(path, handler) answers the HTTP GET for a path with the handler function. It is the smallest unit of an API — the same shape (app.METHOD) is reused for every verb and endpoint.

app.get("/", (req, res) => {   // when GET / arrives...
    res.send("Hello World");    // ...respond with text
});

Routes and HTTP methods

Each verb maps to an action. The full method table and CRUD mapping are owned by REST API.

// GET → read data
app.get("/api/users", (req, res) => {
    res.json({ message: "Get users" });
});

// POST → create data
app.post("/api/users", (req, res) => {
    res.json({ message: "Create user" });
});

// PUT → replace/update data
app.put("/api/users/:id", (req, res) => {
    res.json({ message: "Update user" });
});

// PATCH → update part of data
app.patch("/api/users/:id", (req, res) => {
    res.json({ message: "Update part of user" });
});

// DELETE → delete data
app.delete("/api/users/:id", (req, res) => {
    res.json({ message: "Delete user" });
});

Status codes are documented on REST API. The essentials: 200/201/204 success, 400/401/403/404/409 client errors, 500 server error.

The request object: req

req wraps everything the client sent. Use req.params to identify a resource, req.query to filter/paginate, req.body for create/update data, and req.headers for metadata such as auth tokens.

// URL parameter — part of the path
// GET /api/users/123
app.get("/api/users/:id", (req, res) => {
    console.log(req.params.id);   // "123"
});

// query parameters — after the "?"
// GET /api/users?page=2&limit=10
app.get("/api/users", (req, res) => {
    console.log(req.query.page);   // "2" (strings, not numbers)
    console.log(req.query.limit);  // "10"
});

// request body (needs express.json())
app.post("/api/users", (req, res) => {
    console.log(req.body);   // parsed object from the JSON payload
});

// headers
app.get("/api/users", (req, res) => {
    console.log(req.headers.authorization);  // "Bearer <token>"
});

The response object: res

res builds the reply. Pick the method by payload (send for text/HTML, json for data) and always set the right status code so clients know what happened.

// send text (Content-Type: text/html)
res.send("Hello");

// send JSON (Content-Type: application/json)
res.json({ name: "Alice" });

// status code + JSON — status must come before the body call
res.status(200).json({ message: "Success" });

// error response — 400 tells the client the request was invalid
res.status(400).json({ message: "Bad request" });

// redirect the client to another URL (302)
res.redirect("/login");
Watch out

Send exactly one response per request. Calling res.json() and then res.send() throws "Cannot set headers after they are sent".

Router and mounting

Routers group related routes into their own module. Define the routes, export the router, then mount it under a base path — this keeps server.js small as the API grows.

// routes/userRoutes.js
const express = require("express");
const router = express.Router();   // a mini-app for this resource

router.get("/", (req, res) => {    // relative to the mount path
    res.json({ message: "Get users" });
});

router.post("/", (req, res) => {
    res.json({ message: "Create user" });
});

module.exports = router;   // hand the router back to server.js
// server.js
const userRoutes = require("./routes/userRoutes");

app.use("/api/users", userRoutes);   // prefix every route inside the router

// now available:
// GET  /api/users
// POST /api/users

Controllers and the route → controller flow

A controller is a function that handles a route. Routing files stay thin; controllers hold the logic — this separation is what keeps a real API maintainable.

// routes/userRoutes.js — just wires a path to a handler
router.get("/", getUsers);

// controllers/userController.js — the actual work
const getUsers = async (req, res) => {
    const users = await User.find();
    res.status(200).json(users);   // 200 OK with the data
};
router.get("/", getUsers);
        ↓
const getUsers = async (req, res) => {
    const users = await User.find();
    res.json(users);
};

async / await and try / catch

Database calls are asynchronous, so route handlers are usually async and await the query. Wrap the work in try/catch: without it a failed query becomes an unhandled rejection instead of a clean error response.

router.get("/", async (req, res) => {   // async so we can await
    try {
        const users = await User.find();   // waits for the DB
        res.json(users);
    } catch (error) {
        res.status(500).json({ message: error.message });  // respond, don't crash
    }
});

In larger apps, forward the error with next(error) so the central error handler formats it (see below).

next()

next() hands control to the next middleware or route handler. Use it for guards such as authentication: if the check passes call next(), otherwise respond and stop.

const authMiddleware = (req, res, next) => {
    const token = req.headers.authorization;

    if (!token) {
        return res.status(401).json({ message: "Not authorized" }); // stop here
    }

    next();   // token present -> continue to the route
};

router.get("/profile", authMiddleware, getProfile);

Error-handling middleware

This page owns the central error handler. It is identified by its four parameters: (err, req, res, next). Express calls it whenever a handler passes an error to next(error) or throws synchronously.

app.use((err, req, res, next) => {   // 4 params = error handler
    console.error(err);   // log for debugging

    res.status(err.statusCode || 500).json({   // use the error's status if set
        message: err.message || "Server Error"
    });
});
Warning

Error middleware must have all four parameters. If you declare only three, Express treats it as normal middleware and never calls it for errors.

Note

Register this after all routes so it catches errors from everything above it. A consistent JSON error shape lets the React client show a reliable message.

Static files

express.static serves plain files (images, CSS, a built React dist/) without writing a route for each one. Express maps each file to a URL automatically.

app.use(express.static("public"));   // serve the public/ folder at the site root

Files inside public/ are served directly at the root URL (for example, public/logo.png → /logo.png).

Multiple route params and query params

A path can capture several named segments at once, and query parameters layer on top for options that do not identify the resource. This is how nested resources (a user's orders) and filters are addressed.

// single param
router.get("/users/:id", (req, res) => {
    const { id } = req.params;   // destructure the captured segment
    console.log(id);
});

// multiple params
router.get("/users/:userId/orders/:orderId", (req, res) => {
    const { userId, orderId } = req.params;   // both captured from the path
});
// GET /api/products?category=phone&page=2&limit=10
router.get("/products", (req, res) => {
    const { category, page, limit } = req.query;   // all strings
});

Validation

Never trust the incoming body — the client can send anything. Validate before touching the database so bad data never reaches it and the client gets a clear 400.

router.post("/users", async (req, res) => {
    const { name, email } = req.body;

    if (!name || !email) {
        return res.status(400).json({   // 400 = client sent invalid input
            message: "Name and email are required"
        });
    }
});
Note

For anything beyond a few fields, use a schema validator such as Zod, Joi, or express-validator. See REST API · Validation.

CRUD structure

Every resource follows the same layered path — routes decide the URL, controllers hold logic, models talk to MongoDB. Learning this pattern once lets you add any new resource quickly.

routes
   ↓
controllers
   ↓
models
   ↓
database
// routes/productRoutes.js — one line per CRUD action
router.get("/", getProducts);        // list
router.post("/", createProduct);     // create
router.put("/:id", updateProduct);   // update one
router.delete("/:id", deleteProduct); // delete one

Typical controllers (Product model)

Each controller forwards errors with next(error) so the central error handler responds.

// GET all
const getProducts = async (req, res, next) => {
    try {
        const products = await Product.find();
        res.status(200).json(products);   // 200 OK + array
    } catch (error) {
        next(error);   // hand off to the central error handler
    }
};

// CREATE
const createProduct = async (req, res, next) => {
    try {
        const product = await Product.create(req.body);  // validate first in real code
        res.status(201).json(product);   // 201 Created
    } catch (error) {
        next(error);
    }
};
// GET one
const getProduct = async (req, res, next) => {
    try {
        const product = await Product.findById(req.params.id);

        if (!product) {
            return res.status(404).json({ message: "Product not found" }); // no match
        }

        res.json(product);   // defaults to 200
    } catch (error) {
        next(error);
    }
};

// UPDATE
const updateProduct = async (req, res, next) => {
    try {
        const product = await Product.findByIdAndUpdate(
            req.params.id,
            req.body,
            { new: true, runValidators: true }   // return updated doc + run schema rules
        );
        res.json(product);
    } catch (error) {
        next(error);
    }
};

// DELETE
const deleteProduct = async (req, res, next) => {
    try {
        await Product.findByIdAndDelete(req.params.id);
        res.json({ message: "Product deleted" });   // or 204 with no body
    } catch (error) {
        next(error);
    }
};

CORS

The cors middleware lets the browser frontend call your API from a different origin. Setup only here — the full explanation of the browser same-origin policy belongs to Internet & Web Fundamentals.

const cors = require("cors");

// allow all origins (development)
app.use(cors());

// allow one specific frontend — safer for production
app.use(cors({ origin: "http://localhost:5173" }));

Auth flow and protect middleware

At a high level: the client logs in, the server verifies credentials and returns a token; the client sends that token on later requests; a protect middleware verifies it and attaches the user to req.user. This page keeps only the shape — the full implementation is owned by Authentication & JWT.

const protect = (req, res, next) => {
    const token = req.headers.authorization?.split(" ")[1];  // "Bearer <token>" -> token

    if (!token) {
        return res.status(401).json({ message: "Not authorized" });  // not authenticated
    }

    // verify token, set req.user, then:
    next();   // authenticated -> continue to the controller
};

router.get("/profile", protect, getProfile);
