Data Representation & Encoding

Bits, bytes, binary, hex, ASCII, UTF-8, and Base64 — how computers turn characters, images, and objects into numbers, bytes, and finally physical signals.

Fundamentals Binary & encoding Data formats

The big idea

At the lowest level, a computer stores, processes, and transfers everything as bits — 0 and 1. Eight bits make a byte. But the bits themselves carry no meaning: 01000001 could be the letter A, the number 65, part of an image, part of a program, or part of a network packet. Only a format, encoding, or protocol tells the computer how to interpret the bits.

Key point

Binary is the data representation; the format or encoding gives the data meaning.

Different technologies solve different problems. ASCII, UTF-8, hexadecimal, Base64, JSON, compression, encryption, TCP, IP, and signaling are not the same thing — each serves a specific purpose in the pipeline.

Bits

A bit (binary digit) is the smallest unit of digital information. It has two possible values: 0 or 1. Physically it is often represented by voltage levels, and logically it can represent true/false or on/off.

Single bit: 0 or 1
Two bits:   00, 01, 10, 11
Three bits: 000, 001, 010, 011, 100, 101, 110, 111

Decimal 0 = 0
Decimal 1 = 1
Decimal 2 = 10
Decimal 3 = 11
Decimal 4 = 100

Real-world analogies: a light switch (ON/OFF), a true/false condition, or a single black/white pixel.

Bytes

A byte is most commonly 8 bits and is the basic addressable unit of memory. 28 = 256 combinations, ranging from 0 to 255 unsigned.

00000000 = 0
00000001 = 1
00000010 = 2
11111111 = 255
1 byte  = 8 bits
1 KB    = 1024 bytes
1 MB    = 1024 KB  = 1,048,576 bytes
1 GB    = 1024 MB  = 1,073,741,824 bytes
1 TB    = 1024 GB  = 1,099,511,627,776 bytes

A 32-bit integer takes 4 bytes. For example, decimal 42 is 00000000 00000000 00000000 00101010.

Decimal vs binary prefixes

Decimal (SI) prefixes are powers of 1000, while binary (IEC) prefixes are powers of 1024. Drive and network vendors use decimal sizes, but operating systems report storage in binary, so the same capacity shows a smaller number. Use the matching prefix to avoid confusion.

Decimal (SI):                      Binary (IEC):
KB = 1000 bytes                    KiB = 1024 bytes
MB = 1,000,000 bytes               MiB = 1,048,576 bytes
GB = 1,000,000,000 bytes           GiB = 1,073,741,824 bytes

Binary

Binary is the base-2 number system using only 0 and 1. Each position is a power of 2. Computers use it because digital hardware reliably represents two states.

Binary: 1010
= (1 × 2^3) + (0 × 2^2) + (1 × 2^1) + (0 × 2^0)
= 8 + 0 + 2 + 0
= 10

2^0 = 1    = 00000001
2^1 = 2    = 00000010
2^2 = 4    = 00000100
2^3 = 8    = 00001000
2^4 = 16   = 00010000
2^5 = 32   = 00100000
2^6 = 64   = 01000000
2^7 = 128  = 10000000

Binary arithmetic works the same way as decimal:

Decimal

Decimal is base-10, using digits 0–9. It is intuitive for humans and mainly used for human interaction.

Number: 5,283
= (5 × 10^3) + (2 × 10^2) + (8 × 10^1) + (3 × 10^0)
= 5000 + 200 + 80 + 3
= 5,283

Hexadecimal

Hexadecimal (hex) is base-16, using 0–9 and A–F (A=10 … F=15). Each hex digit represents exactly 4 bits (a nibble), making binary far more compact to read. Prefixes are common: 0x (C/Java), # (CSS), h (assembly).

A3 = 10100011  (163 decimal)

Converting between bases

Converting is just repeatedly dividing by the target base and reading the remainders. You rarely do this by hand, but understanding it explains why hex maps so cleanly onto binary and how JavaScript's parseInt/toString switches bases.

Decimal 13 → Binary
13 ÷ 2 = 6  remainder 1
6  ÷ 2 = 3  remainder 0
3  ÷ 2 = 1  remainder 1
1  ÷ 2 = 0  remainder 1
Read bottom to top: 1101

Decimal 255 → Hex
255 ÷ 16 = 15 remainder 15
15 = F
255 decimal = FF

Binary 11001101 → Decimal
= 128 + 64 + 0 + 0 + 8 + 4 + 0 + 1
= 205
parseInt("1010", 2);          // 10   binary string to decimal
(10).toString(2);             // "1010"  decimal to binary string
(255).toString(16);           // "ff"    decimal to hex string
parseInt("FF", 16);           // 255  hex string to decimal

Bitwise operations

Bitwise operators work on each bit position independently instead of on the whole number. They are used for flags/permissions, masks, and low-level encoding — for example checking whether a permission bit is set with flags & MASK.

AND (&):        1010 & 1100 = 1000
OR  (|):        1010 | 1100 = 1110
XOR (^):        1010 ^ 1100 = 0110
NOT (~):        ~1010       = 0101  (4-bit illustration)

5 & 3;   // 1   (0101 & 0011)
5 | 3;   // 7   (0101 | 0011)
5 ^ 3;   // 6   (0101 ^ 0011)
~5;      // -6  (two's complement: ~x === -x - 1)
1 << 3;  // 8   (left shift = multiply by 2)
8 >> 1;  // 4   (right shift = divide by 2)
Watch out

JavaScript bitwise operators first convert numbers to 32-bit signed integers, so they are only safe for values within that range. Prefer >>> (unsigned shift) when you must avoid sign propagation.

ASCII

ASCII (American Standard Code for Information Interchange) is a character encoding that maps characters to numbers. It uses 7 bits for 128 characters (extended ASCII uses 8 bits).

'A' = 65  = 0x41 = 01000001
'B' = 66  = 0x42 = 01000010
'a' = 97  = 0x61 = 1100001
'0' = 48  = 0x30 = 0110000
' ' = 32  = 0x20 = 0100000

ASCII and binary are not competing systems. ASCII answers "which numeric value represents this character?" while binary answers "how is that number represented in 0s and 1s?"

Warning

ASCII only covers English and a few symbols. It does not support accents, emojis, or non-Latin scripts (Arabic, Chinese, Hindi, etc.).

Character vs number

These are different values:

Character "5" → ASCII code 53 → 00110101
Number 5      → binary          → 00000101

UTF-8

UTF-8 (Unicode Transformation Format – 8-bit) is a variable-length encoding (1–4 bytes) that can represent every Unicode character. It is backward compatible with ASCII and used by the vast majority of the web.

1-byte: 0xxxxxxx                             (0-127, ASCII)
2-byte: 110xxxxx 10xxxxxx                    (128-2047)
3-byte: 1110xxxx 10xxxxxx 10xxxxxx           (2048-65535)
4-byte: 11110xxx 10xxxxxx 10xxxxxx 10xxxxxx  (65536-1114111)
'A' = 0x41                    (1 byte, same as ASCII)
'ñ' = 0xC3 0xB1               (2 bytes)
'€' = 0xE2 0x82 0xAC          (3 bytes)
'😊' = 0xF0 0x9F 0x98 0x8A     (4 bytes)

"Hello" = 48 65 6C 6C 6F      (5 bytes)
"世界"   = E4 B8 96 E7 95 8C    (6 bytes)

UTF-8 is efficient for English (1 byte per character), self-synchronizing, and compatible with ASCII for the ASCII range — which is why it became the default.

Base64

Base64 represents arbitrary binary data using 64 printable ASCII characters (A–Z, a–z, 0–9, +, /, with = for padding). Each Base64 character carries 6 bits: input bytes are grouped into 24-bit chunks and split into four 6-bit groups.

Walkthrough: encoding "Man"

This walks the algorithm end to end: three text bytes (24 bits) are regrouped into four 6-bit values, and each value maps to one Base64 character. It shows why every 3 input bytes become exactly 4 output characters.

Text:    M     a     n
ASCII:   77    97    110
Binary:  010011 010110 000101 101110
Index:   19     22     5      46
Base64:  T      W      F      u
Result:  "TWFu"

Walkthrough: encoding "Hello"

The same method applied to five bytes. The final group is short, so the output is padded with = to reach a 4-character boundary, which is why Base64 length is always a multiple of four.

Input:  "Hello"
ASCII:  72 101 108 108 111
Binary: 01001000 01100101 01101100 01101100 01101111
Groups: 010010 000110 010101 101100 011011 000110 111100
Index:  18 6 21 44 27 6 60
Base64: S  G  V  s  b  G  8
Padding: =
Result: "SGVsbG8="

Common uses

Base64 appears wherever binary data must travel through a text-only channel. These are the cases you will meet most often, from embedding images to carrying token segments.

# Email attachments (MIME)
Content-Transfer-Encoding: base64

# Data URIs in HTML
<img src="data:image/png;base64,iVBORw0KGgo...">

# JWT segments
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxIn0...

# Basic authentication
Authorization: Basic QWxhZGRpbjpvcGVuIHNlc2FtZQ==  (Aladdin:open sesame)
Warning

Base64 is an encoding, not encryption. It increases size by about 33% and provides no security by itself.

Text vs image: same bits, different format

A photo is also ultimately binary. JPEG provides rules telling the receiver "these bytes describe a JPEG image"; UTF-8 provides rules telling the receiver "these bytes represent these characters." Both become bytes, then bits.

Why do we need ASCII if we send binary anyway?

We do send binary. ASCII does not exist because computers cannot send binary — they certainly can. ASCII provides the meaning of the binary data when that data represents text. It is a shared dictionary between systems:

Encoding vs serialization vs compression vs encryption

These four are constantly confused because they all "turn data into other bytes." Each solves a different problem, and a single request often uses all of them in sequence.

TechnologyConvertsProblem it solves
Character encoding (ASCII, UTF-8)Characters → bytesHow do I represent text as numbers?
Serialization (JSON, XML, Protobuf)Data structures → byte stream/textHow do I send a complex object over the network?
Compression (GZIP, DEFLATE)Removes redundancyHow do I send data faster using fewer bytes?
Encryption (AES, TLS)Plaintext → ciphertextHow do I keep data confidential in transit?

Compression (optional): GZIP
Encryption (TLS):       encrypted bytes
Transmission:           TCP → IP → Ethernet → bits

Key point

Binary answers "how is digital information represented?" Encoding/format answers "what do these bits mean?" Protocols answer "how do different computers communicate and interpret the data?"

Quick recap

  • A bit is 0 or 1; 8 bits make a byte (256 values, 0–255).
  • Binary is base-2, decimal is base-10, hex is base-16 (one hex digit = 4 bits).
  • Bitwise AND, OR, XOR, NOT, and shifts operate directly on bits.
  • ASCII maps English characters to numbers; UTF-8 encodes all Unicode and is ASCII-compatible.
  • Base64 encodes arbitrary binary as printable ASCII using 6 bits per character.
  • Bits have no meaning without a format; text, images, audio, and video each use their own rules.
  • Encoding, serialization, compression, and encryption are four different problems.
  • Ultimately everything becomes bytes, then bits, then physical signals.
