Networking Layers

TCP, IP, MAC, ARP, DHCP, NIC, NAT, and encapsulation — how software data becomes physical signals and how each layer answers a different question.

Fundamentals TCP/IP model Networking

The big picture

When an application such as Chrome or Node.js communicates over a network, data passes down through several layers. Each layer has a different responsibility and adds its own header (or header and trailer).

TCP — Transmission Control Protocol

TCP is a transport-layer protocol, not a physical device. It is implemented mainly as software inside the operating system's networking stack.

Operating System
│
└── Networking Stack
      ├── TCP
      ├── UDP
      ├── IP
      └── Other networking functionality

TCP provides:

  • Ordering data
  • Detecting missing data
  • Retransmitting lost data
  • Acknowledging received data (ACKs)
  • Flow control
  • Congestion control
  • Connection management

TCP uses port numbers to identify applications/services. Ports are 16-bit numbers (0–65535); TCP and UDP each have their own port space, and ports below 1024 are privileged/reserved for system services while clients pick a random high port for outgoing connections. Port 443 is commonly HTTPS.

Source port:      50000
Destination port: 443

Application data plus a TCP header forms a TCP segment:

┌──────────────────────────────┐
│ TCP Header                   │
│ source port: 50000           │
│ destination port: 443        │
│ sequence number: ...         │
│ acknowledgement: ...         │
│ flags: ...                   │
├──────────────────────────────┤
│ HTTP data                    │
│ GET / HTTP...                │
└──────────────────────────────┘
Key point

Reliability comes from three ideas working together: sequence numbers (ordering), acknowledgements (confirmation), and retransmission (recovery of lost segments).

The TCP three-way handshake

Before any data flows, TCP establishes a connection with a three-way handshake. Both sides exchange initial sequence numbers so each can order and acknowledge the other's data.

Client                                Server
   │ ──── SYN (seq=100) ──────────→ │   "connect; my seq is 100"
   │ ←─── SYN-ACK (seq=300,ack=101) │   "OK; my seq is 300, I got your 100"
   │ ──── ACK (ack=301) ──────────→ │   "confirmed; connection open"
   │ ===== connection established == │
  1. SYN — the client sends a synchronize packet with an initial sequence number to the target port (for example 443).
  2. SYN-ACK — the server acknowledges the client's sequence and sends its own SYN with its own initial sequence number.
  3. ACK — the client acknowledges the server's sequence; the connection is open.

For HTTPS, the TLS handshake happens after the TCP handshake, and then the HTTP request follows. A connection is closed with a FIN/ACK exchange.

Key point

The three-way handshake is why TCP is called connection-oriented: both sides agree on sequence numbers before sending data, which is what makes ordering, acknowledgements, and retransmission possible.

IP — Internet Protocol

IP is a network-layer protocol. Like TCP it is implemented largely as software in the OS networking stack, while routers implement IP forwarding. IP provides logical addressing, packet delivery, and routing/forwarding between networks.

Do not confuse IP (the protocol) with an IP address (the logical address it uses). 192.168.1.25 is an IPv4 address.

IP networks and prefixes

An IP network is a logical network defined by a prefix/subnet. In 192.168.1.0/24 the first 24 bits are the network prefix and the rest identify interfaces/hosts. Two devices at 192.168.1.25 and 192.168.1.30 can share the same network.

Routing

If a destination is outside the computer's local IP network, the computer sends traffic toward its default gateway (usually a router). The router examines the destination IP and forwards the packet using its routing information.

192.168.1.25

Router
192.168.1.1
      ↓

Destination network
      ↓

IP address types

IPv4 address classes

ClassRangeTypical use
A1.0.0.0 – 126.255.255.255 (/8)Large networks
B128.0.0.0 – 191.255.255.255 (/16)Medium networks
C192.0.0.0 – 223.255.255.255 (/24)Small networks
D224.0.0.0 – 239.255.255.255Multicast
E240.0.0.0 – 255.255.255.255Reserved

Private ranges and special addresses

Some IPv4 ranges are reserved rather than globally routable. Private ranges are reused inside every home or office network behind NAT, while the special addresses have fixed meanings such as loopback and broadcast.

10.0.0.0/8        - 10.0.0.0 to 10.255.255.255
172.16.0.0/12     - 172.16.0.0 to 172.31.255.255
192.168.0.0/16    - 192.168.0.0 to 192.168.255.255

0.0.0.0           - Default route
127.0.0.1         - Localhost / loopback
255.255.255.255   - Broadcast
169.254.0.0/16    - Link-local (APIPA)

0.0.0.0 has a second, very common meaning when a service binds to it: "listen on all network interfaces." By contrast 127.0.0.1 binds a service to the loopback interface only, so it is reachable only from the same machine. This is why an app bound to 127.0.0.1 is not directly reachable from the Internet.

IPv6 address types

IPv6 groups addresses by scope rather than by class. The prefix decides whether an address is Internet-routable, private, local to a link, one-to-many, or delivered to the nearest of several hosts.

Global Unicast: 2000::/3 - Internet-routable
Unique Local:   FC00::/7 - Private
Link-Local:     FE80::/10 - Local network only
Multicast:      FF00::/8 - One-to-many
Anycast:        Same as global, but multiple destinations

MAC address

MAC (Media Access Control) is a link-layer address associated with a network interface, e.g. 3C:52:82:AB:12:34. A 48-bit MAC splits into an OUI (manufacturer) and a NIC-specific part.

XX:XX:XX:YY:YY:YY
│       │  │
│       │  └─ NIC-specific (24 bits)
│       └──── Manufacturer-specific (24 bits)
└──────────── OUI (Organizationally Unique Identifier)

Example: B8:27:EB:12:34:56
OUI: B8:27:EB (Raspberry Pi Foundation)
NIC-Specific: 12:34:56

MAC addresses come in three types:

TypeRuleExample
UnicastFirst byte even02:00:00:00:00:00
MulticastFirst byte odd01:00:00:00:00:00
BroadcastAll bits setFF:FF:FF:FF:FF:FF
Watch out

A MAC address is flat and link-local — it is not routable across the Internet. You reach a host by IP; you use its MAC only to hand the frame to the next device on the same link.

ARP and NDP

For IPv4, a host uses ARP (Address Resolution Protocol) to discover the MAC address of a local IP. It broadcasts a request and the owner replies:

Request (broadcast): "Who has 192.168.1.1? Tell 192.168.1.20"
Reply (unicast):     "192.168.1.1 is at BB:BB:BB:BB:BB:BB"

The mapping is cached in the ARP table:

IP Address         MAC Address
192.168.1.1        BB:BB:BB:BB:BB:BB
192.168.1.21       CC:CC:CC:CC:CC:CC
# Windows
> arp -a

# Linux / macOS
$ arp -n
┌─────────────────────────────────────────────┐
│ Hardware Type (Ethernet = 1)               │
├─────────────────────────────────────────────┤
│ Protocol Type (IPv4 = 0x0800)              │
├─────────────────────────────────────────────┤
│ Operation (Request = 1, Reply = 2)         │
├─────────────────────────────────────────────┤
│ Source MAC Address                         │
├─────────────────────────────────────────────┤
│ Source IP Address                          │
├─────────────────────────────────────────────┤
│ Target MAC Address (Unknown = 00:00:00:00) │
├─────────────────────────────────────────────┤
│ Target IP Address                          │
└─────────────────────────────────────────────┘

Other ARP variants:

  • Gratuitous ARP — announced when an IP changes, an interface comes online, or to detect duplicate IPs.
  • Proxy ARP — a router answers on behalf of a device on another segment.

IPv6 uses NDP (Neighbor Discovery Protocol) instead of ARP:

Neighbor Solicitation:  "Who has 2001:db8::1?"
Neighbor Advertisement: "I have it, my MAC is BB:BB:BB:BB:BB:BB"

IP vs MAC — why both

IP and MAC are not alternatives. They describe the same transmission from different layers:

IP  → Where am I trying to send the packet? (logical, end-to-end)
MAC → Which device should receive this frame on this local link? (physical, per-hop)

They work like nested envelopes: the outer envelope (MAC) is addressed to the next local device, while the inner envelope (IP) is addressed to the final destination.

Outer Envelope (MAC):
    To:  BB:BB:BB:BB:BB:BB (Router)
    From: AA:AA:AA:AA:AA:AA (Laptop)

    Inner Envelope (IP):
        To: 192.168.1.1 (Router)
        From: 192.168.1.20 (Laptop)

        Message: "Hello!"

IP alone is not enough: it is logical, can change, and provides no physical hardware address. MAC alone is not enough: it is flat, local to a segment, and provides no routing information.

AspectIP addressMAC address
LayerNetwork (3)Data Link (2)
TypeLogicalPhysical
Assigned byAdministrator / DHCPManufacturer
ChangeableYesUsually no
Length32 bits (IPv4) / 128 bits (IPv6)48 bits
Format192.168.1.1AA:BB:CC:DD:EE:FF
ScopeGlobal (or private)Local only
RoutingUsed for routingNot used for routing
Key point

IP is also used inside a home LAN — not only on the Internet. Even laptop-to-printer traffic uses both IP and MAC.

MAC changes at every hop

When the destination is remote, the laptop's IP packet is addressed to the final server, but the local frame is addressed to the router:

IP:
192.168.1.20 → 8.8.8.8

MAC:
AA:AA:AA:AA:AA:AA → BB:BB:BB:BB:BB:BB  (router)

The router removes the old link frame, keeps the IP packet intact, and builds a new frame for the next link.

Original MAC:   AA → BB
   ↓
Next Link MAC:  CC → DD
   ↓
Next Link MAC:  EE → FF
   ↓
Final Link MAC: GG → HH
HopMAC source → destinationIP source → destination
1AA:AA → BB:BB192.168.1.20 → 8.8.8.8
2CC:CC → DD:DD192.168.1.20 → 8.8.8.8
3EE:EE → FF:FF192.168.1.20 → 8.8.8.8
4GG:GG → HH:HH192.168.1.20 → 8.8.8.8

Analogy: your final destination (IP) stays the same, but each connecting flight (MAC) changes at every stop.

DHCP and the DORA process

DHCP (Dynamic Host Configuration Protocol) automatically provides network configuration to devices: IP address, subnet mask/prefix, default gateway, DNS server, and lease duration.

In a typical home network, the Wi-Fi router itself acts as the DHCP server. DHCP does not create the Internet connection — it provides the configuration that lets a device participate in the network.

NAT and PAT

NAT (Network Address Translation) is a separate function from MAC addressing — it changes the source IP (usually at the router).

Before NAT:
IP:  192.168.1.20 → 8.8.8.8
MAC: AA:AA:AA:AA:AA:AA → BB:BB:BB:BB:BB:BB

After NAT (at router):
IP:  203.0.113.1 → 8.8.8.8
MAC: CC:CC:CC:CC:CC:CC → DD:DD:DD:DD:DD:DD

LayerNetworkData Link
ChangesSource IP (outbound)Source/Destination MAC

PAT (Port Address Translation) lets many devices share one public IP by mapping distinct source ports:

Device 1: 192.168.1.20:54321 → 203.0.113.1:12345
Device 2: 192.168.1.21:54322 → 203.0.113.1:12346

  1. The laptop checks its routing table and picks the default route via 192.168.1.1.
  2. It resolves the router's MAC with ARP.
  3. It builds a frame whose destination MAC is the router.
  4. The router decapsulates, checks the destination IP, and forwards the packet toward the next hop.
  5. On each new link a new frame (with new MAC addresses) is created until the server is reached.

Applications vs protocols vs hardware

These three are easy to blur together. An application is software that uses the network; a protocol is an agreed set of rules for communicating; hardware is the physical gear that moves the signals. Chrome is not a protocol, and HTTP is not hardware.

CategoryExamplesRole
ApplicationChrome, Firefox, Node.js appUses networking
ProtocolHTTP, TCP, IP, DHCP, DNSDefines communication rules
HardwareNIC, router, switch, fiber equipmentPhysically participates

HTTP is an application-layer protocol; TCP is transport-layer. They are different layers with different jobs. A useful split:

TCP → ports, ordering, reliability, retransmission, flow/congestion control
IP  → IP addresses, packet forwarding/routing

TCP: "How do I provide transport between applications?"
IP:  "Which logical destination should receive this packet, and where to forward it?"
Note

IP ≠ Internet. IP is a protocol; the Internet is a huge network of networks that uses IP alongside many other protocols.

OSI model vs the TCP/IP model

The OSI model is a seven-layer teaching model; the TCP/IP model the Internet actually uses is a coarser four-layer view. They map onto each other like this:

TCP/IP layerOSI layer(s)Examples
ApplicationApplication, Presentation, Session (7, 6, 5)HTTP, HTTPS, DNS, SMTP
TransportTransport (4)TCP, UDP
InternetNetwork (3)IP, ICMP, ARP
Network AccessData Link + Physical (2, 1)Ethernet, Wi-Fi, the NIC

TLS sits between the application and transport layers: HTTP rides on top of TLS, and TLS rides on top of TCP. That is why HTTPS is often described as "HTTP over TLS over TCP over IP".

The most important distinction

If you remember one thing from this page, remember the separation of responsibilities:

  • IP address = the logical, end-to-end destination that stays (mostly) constant across the whole journey. It tells routers where the packet ultimately needs to go.
  • MAC address = the physical, link-local destination for the current hop only. It tells the current network segment which interface should receive this frame right now.

This is why every hop rewrites the MAC addresses but leaves the IP packet (apart from NAT) untouched. IP scales across the entire Internet because it is hierarchical and routable; MAC stays simple and flat because it only has to identify hardware on one link.

Key point

MAC changes at every hop; IP (destination) stays the same end-to-end. That single sentence explains why both addresses are required.

Final mental model

Each layer answers a different question:

HTTP               "What application message am I sending?"
TCP                "Which application/service is communicating, and how do I
                    provide reliable transport?"
IP                 "Which logical network destination should receive this packet,
                    and where should it be forwarded?"
Ethernet/Wi-Fi     "Which device on this local link should receive this frame?"
NIC                "How do I transmit the frame using this network technology?"
Physical layer     "How do I represent the bits as physical signals?"

Quick recap

  • TCP is a transport protocol (software in the OS) that provides ordering, ACKs, retransmission, and flow/congestion control.
  • TCP opens a connection with a three-way handshake (SYN, SYN-ACK, ACK) before any data flows.
  • The 7-layer OSI model maps onto the 4-layer TCP/IP model; TLS sits between application and transport.
  • IP is a network protocol that provides logical addressing and routing; an IP address is not the protocol.
  • MAC is a flat, link-local hardware address; ARP (IPv4) and NDP (IPv6) map IP to MAC.
  • IP is the end-to-end logical destination; MAC is the per-hop local destination.
  • MAC addresses change at every hop; the destination IP stays the same.
  • DHCP (DORA) hands out IP, gateway, and DNS configuration.
  • The NIC is the hardware; encapsulation wraps data at each layer and decapsulation unwraps it at the receiver.
  • NAT/PAT translate source IP/ports; they are separate from MAC addressing.
