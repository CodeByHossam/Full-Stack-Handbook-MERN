MongoDB Basics

Documents, collections, shell CRUD, query operators, and the beginner Mongoose layer that connects Express to MongoDB.

Database NoSQL Shell + Mongoose

How MongoDB is organized

MongoDB is a NoSQL, document-oriented database. Instead of tables and rows it stores JSON-like objects called documents. At the storage level those documents are encoded as BSON (Binary JSON), which adds types like dates and ObjectIds.

Database
   └── Collections
          └── Documents
                 └── Fields

Compared with SQL, the vocabulary maps like this:

SQLMongoDB
DatabaseDatabase
TableCollection
RowDocument
ColumnField
Key point

A collection holds many documents, and documents in the same collection do not have to share an identical shape. That flexibility is the main difference from SQL.

Shell basics

The mongosh shell is the fastest way to inspect a database while developing.

  • What: an interactive REPL where you type JavaScript-style commands straight against the server.
  • Why: you can check data, indexes, or a failing query without writing any app code.
  • When: during development and debugging; real application changes should come from your app or a migration.
// show every database on the server
show dbs;

// create (or switch to) a database
use myDatabase;

// show the current database
db;

// list collections in the current database
show collections;
Note

A database is only created on disk once it contains at least one collection with data.

Collections

You can create a collection explicitly, or let MongoDB create it the first time you insert a document.

Create it explicitly when you need options such as capped size, validation, or a custom collation up front; implicit creation is the zero-config default and happens on the first insertOne().

// explicit creation
db.createCollection("users");

// implicit creation — the users collection appears automatically
db.users.insertOne({
    name: "Alice",
    age: 42
});

Insert documents

Use insertOne() for a single document and insertMany() for a batch.

Each insert returns an acknowledgement and the generated _id(s). insertMany() writes the whole array in one round trip, so prefer it for seeds and bulk imports over a loop of insertOne().

// insert one
db.users.insertOne({
    name: "Alice",
    email: "alice@example.com",
    age: 42
});

// insert many
db.users.insertMany([
    { name: "Bob", age: 30 },
    { name: "Carol", age: 25 }
]);

Find documents

find() returns a cursor of matches; findOne() returns the first match or null.

A cursor streams documents lazily instead of loading them all into memory, which is why you chain sort/limit onto it and usually call .toArray() only when you truly need the whole result.

// all documents
db.users.find();

// one document
db.users.findOne();

// by a single condition
db.users.find({ age: 42 });

// by multiple conditions (implicit AND)
db.users.find({ age: 42, name: "Alice" });

Comparison operators

Comparison operators wrap the value inside a field condition, e.g. { age: { $gt: 30 } }. Reach for them whenever the match is a range or a set rather than exact equality.

OperatorMeaning
$gtGreater than
$gteGreater than or equal
$ltLess than
$lteLess than or equal
$neNot equal
$inMatches any value in a list
$ninMatches none of the values in a list
 
db.users.find({ age: { $gt: 30 } });          // greater than
db.users.find({ age: { $gte: 30 } });         // greater than or equal
db.users.find({ age: { $lt: 30 } });          // less than
db.users.find({ age: { $lte: 30 } });         // less than or equal
db.users.find({ age: { $ne: 30 } });          // not equal
db.users.find({ age: { $in: [20, 30, 40] } });   // in a list
db.users.find({ age: { $nin: [20, 30, 40] } });  // not in a list

Logical operators

Combine conditions with $and, $or, and $not.

You only need an explicit $and array when the same field appears more than once — listing separate fields is already an implicit AND, as in the age range below.

// AND
db.users.find({
    $and: [
        { age: { $gte: 18 } },
        { age: { $lte: 50 } }
    ]
});

// OR
db.users.find({
    $or: [
        { age: 20 },
        { age: 30 }
    ]
});

// NOT
db.users.find({
    age: { $not: { $gt: 30 } }
});

Update documents

An update call takes a filter and an update document. The $set operator changes or adds fields. Use updateOne() to touch one document and updateMany() to touch every match.

// update one
// the second argument must use update operators; a plain object replaces the whole document
db.users.updateOne(
    { name: "Alice" },
    { $set: { age: 43 } }
);

// update many
db.users.updateMany(
    { age: { $lt: 18 } },
    { $set: { status: "minor" } }
);

Update operators

Update operators describe only the change to make, so two concurrent writes touching different fields do not clobber each other the way a full-document replace would.

OperatorEffect
$setSet a field to a new value (creates it if missing)
$unsetRemove a field from the document
$incIncrement (or decrement with a negative value) a number
 
// $set → change or add a field
db.users.updateOne(
    { name: "Alice" },
    { $set: { city: "Abu Dhabi" } }
);

// $unset → remove a field
db.users.updateOne(
    { name: "Alice" },
    { $unset: { city: "" } }
);

// $inc → increase / decrease a number
db.products.updateOne(
    { name: "Laptop" },
    { $inc: { stock: -1 } }
);

Delete documents

A delete removes every document matching the filter and returns the count that was removed. There is no undo, and running it again with the same filter simply deletes nothing.

// delete one
db.users.deleteOne({ name: "Alice" });

// delete many
db.users.deleteMany({ age: { $lt: 18 } });
Warning

An empty filter, deleteMany({}), removes every document in the collection. Double-check the filter before running it.

Array operators

Fields can hold arrays. Use $push, $addToSet, and $pull to modify them.

const product = {
    name: "Laptop",
    tags: ["computer", "electronics"]
};

// add an item with $push (allows duplicates)
db.products.updateOne(
    { name: "Laptop" },
    { $push: { tags: "technology" } }
);

// add only if it does not already exist
db.products.updateOne(
    { name: "Laptop" },
    { $addToSet: { tags: "technology" } }
);

// remove a specific item
db.products.updateOne(
    { name: "Laptop" },
    { $pull: { tags: "computer" } }
);

Sort, limit, and skip

These are chainable cursor methods. 1 sorts ascending and -1 descending.

db.users.find().sort({ age: 1 });   // ascending
db.users.find().sort({ age: -1 });  // descending

db.users.find().limit(10);

Combine skip() and limit() for pagination:

db.users.find().skip(10).limit(10);

// Page 1 → skip(0).limit(10)
// Page 2 → skip(10).limit(10)
// Page 3 → skip(20).limit(10)

Count documents

countDocuments() counts matching documents on the server without transferring them, so it is far cheaper than fetching an array and reading its length.

db.users.countDocuments();

// count with a condition
db.users.countDocuments({ age: { $gte: 18 } });

Projection

Projection controls which fields are returned. Use 1 to include and 0 to exclude.

// return only name and email
db.users.find({}, { name: 1, email: 1 });

// hide the password field
db.users.find({}, { password: 0 });
Common mistake

Do not mix inclusion and exclusion in the same projection (except for _id). Pick one style per query.

Regex search

A regular expression matches part of a string rather than the whole value. Use it for quick pattern matching on small fields; it is a collection scan, not an indexed lookup.

// names starting with "A"
db.users.find({ name: /^A/ });

// case-insensitive search
db.users.find({
    name: { $regex: "alice", $options: "i" }
});
Warning

Unanchored, case-insensitive regex cannot use an index and becomes slow on large collections. For real search use a text index or Atlas Search.

ObjectId

Every document gets an _id automatically. The default type is an ObjectId — a 12-byte value often shown as a 24-character hex string.

// MongoDB generates this for every inserted document
_id: ObjectId("...")

// find by id
db.users.findOne({ _id: ObjectId("65f1c2b3d4e5f6a7b8c9d0e1") });
Key point

An ObjectId string must be a valid 24-character hexadecimal value. Never invent one for testing — copy a real _id.

Embedded documents

A document can contain nested objects. Query nested fields with dot notation.

Embedding keeps related data in the same document so one read returns everything. Choose it when the nested data is always read with the parent; use a reference instead when it is large, shared, or updated independently.

{
    name: "Alice",
    address: {
        city: "Abu Dhabi",
        country: "UAE"
    }
}

// query a nested field with dot notation
db.users.find({ "address.city": "Abu Dhabi" });

Data model example

A typical product document mixes simple fields, arrays, and a nested object.

Seeing all three shapes together is the point: a document is not a fixed row, it can hold whatever structure the domain needs.

{
    name: "Laptop",
    price: 1000,
    category: "Electronics",
    stock: 20,
    tags: ["computer", "technology"],
    seller: {
        name: "ABC Store"
    }
}

Mongoose schema and model

In a MERN app you almost never talk to MongoDB from Express directly. Mongoose sits between Node/Express and MongoDB and adds schemas, validation, and clean JavaScript APIs.

React
   ↓
Express / Node
   ↓
Mongoose
   ↓
MongoDB
const mongoose = require("mongoose");

const userSchema = new mongoose.Schema({
    name: {
        type: String,
        required: true
    },
    email: {
        type: String,
        required: true,
        unique: true
    },
    age: {
        type: Number,
        default: 0
    }
});

// compile the schema into a Model; Mongoose maps "User" to the "users" collection
const User = mongoose.model("User", userSchema);
Note

Connecting Mongoose to your cluster and storing credentials in environment variables is covered in the Database Complete Reference and Node.js.

Mongoose CRUD

Mongoose mirrors the shell operations with promise-based methods.

// CREATE
const user = await User.create({
    name: "Alice",
    email: "alice@example.com",
    age: 42
});

// READ
const users = await User.find();
const one = await User.findOne({ email: "alice@example.com" });
const byId = await User.findById(id);

// UPDATE
await User.findByIdAndUpdate(
    id,
    { $set: { age: 43 } },
    { new: true }   // return the updated document, not the old one
);

// DELETE
await User.findByIdAndDelete(id);
Key point

Pass { new: true } to findByIdAndUpdate() to get the updated document back instead of the old one.

Mongoose query chaining

A Mongoose query can be built up with chained methods before it runs.

Chaining lets you assemble the query conditionally — for example only adding .skip() when a page number is present — and the single await still triggers one database call.

const users = await User.find({ age: { $gte: 18 } })
    .sort({ age: -1 })
    .skip(0)
    .limit(10);

Mongoose populate

When one document references another by ObjectId, populate() replaces the id with the referenced document — the MongoDB equivalent of a JOIN.

// Product.seller holds a User id
const products = await Product.find().populate("seller");
Note

Advanced populate — selective fields, multiple references, populate on a document, and populate after create() — lives in MongoDB & Mongoose Deep Dive.

Mongoose aggregation

The aggregation pipeline processes documents in stages such as $match and $group.

Use it when you need to reshape or summarize on the server instead of pulling documents into Node; each stage feeds the next, so filter early with $match to keep it cheap.

const result = await Product.aggregate([
    { $match: { stock: { $gt: 0 } } },
    {
        $group: {
            _id: "$category",
            total: { $sum: 1 }
        }
    }
]);

Indexes

Indexes make lookups fast at the cost of storage and slightly slower writes. Index the fields you query and sort on.

userSchema.index({ email: 1 });

// unique index
userSchema.index({ email: 1 }, { unique: true });
Key point

The unique: true option in a schema is a shortcut for creating a unique index. It does not make comparisons case-insensitive — see the Deep Dive page.

Credentials and deployment

A real app keeps the connection string in an environment variable and never commits it. The full walkthrough for env files and secrets is on the Node.js page, and where the database layer fits in a project is on MERN Architecture.

Warning

Never hardcode mongodb+srv://user:password@... in source. Use process.env.MONGO_URI and add .env to .gitignore.

Quick recap

  • Structure: database → collections → documents → fields (BSON).
  • Shell basics: show dbs, use, show collections.
  • CRUD: insertOne/Many, find/findOne, updateOne/Many, deleteOne/Many.
  • Comparison: $gt $gte $lt $lte $ne $in $nin; logical: $and $or $not.
  • Updates: $set $unset $inc; arrays: $push $addToSet $pull.
  • Refine results with sort, limit, skip, projection, regex, and countDocuments.
  • Every document has an auto-generated ObjectId; nested fields use dot notation.
  • Mongoose adds a schema/model layer: create/find/findById/findByIdAndUpdate/findByIdAndDelete, chaining, populate, aggregation, and indexes.
  • Keep the connection string in .env; advanced populate and authorization live on the Deep Dive page.
