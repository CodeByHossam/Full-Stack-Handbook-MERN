React Native

Build native Android and iOS apps with React and JavaScript from one codebase — rendering real mobile components instead of HTML.

Frontend Mobile

Create a project (Expo)

Modern React Native projects commonly use Expo.

npx create-expo-app@latest MyApp
cd MyApp
npx expo start
Warning

React Native is not HTML. You don't use <div>, <span> or <p> — you use native components like <View>, <Text> and <Pressable>.

Core components: View & Text

React Native has no HTML tags — you compose platform-native views. Almost every screen is built from a few primitives: View for layout and containers, Text for any text, plus Image and the touchable components below. Unlike HTML, loose text is not allowed: text must live inside Text.

import { View, Text } from "react-native";

export default function App() {
    return (
        <View>   {/* layout container, roughly like a div */}
            <Text>Hello React Native</Text>   {/* all text goes here */}
        </View>
    );
}
  • <View> is the equivalent idea to a <div> — a native layout container.
  • <Text> holds text. Plain text must normally be inside <Text>; don't put it directly inside <View>.

Image, Button, Pressable & TouchableOpacity

These are the visual and interactive primitives. Image shows a remote picture (uri) or a bundled asset (require); Button is a quick built-in; Pressable and TouchableOpacity are touch wrappers around whatever content you put inside.

import { Image, Button, Pressable, Text, TouchableOpacity } from "react-native";

<Image
    source={{ uri: "https://example.com/image.jpg" }}   // remote image
    style={{ width: 200, height: 200 }}                 // size is required
/>

// Local image
<Image source={require("./assets/logo.png")} />

<Button
    title="Click Me"
    onPress={() => console.log("Clicked")}   // native event is onPress, not onClick
/>

<Pressable onPress={() => console.log("Pressed")}>
    <Text>Click Me</Text>
</Pressable>

<TouchableOpacity onPress={() => {}}>
    <Text>Press</Text>
</TouchableOpacity>

<Pressable> is the flexible, modern choice for custom buttons, cards, menus and other interactive elements; TouchableOpacity is the older alternative.

Styles & StyleSheet

React Native doesn't use CSS files; styles are JavaScript objects with camelCase properties.

<View style={{ backgroundColor: "white", padding: 20 }}></View>   {/* inline object */}

import { StyleSheet, View } from "react-native";

<View style={styles.container}></View>

const styles = StyleSheet.create({
    container: {
        flex: 1,                     // fill available space
        backgroundColor: "#fff",     // camelCase, not background-color
        padding: 20
    }
});

Common style properties: backgroundColor, color, fontSize, fontWeight, width, height, padding, margin, borderRadius, borderWidth, borderColor, opacity. StyleSheet.create is recommended for organized styling.

Flexbox in React Native

The Flexbox concepts are owned by CSS → Flexbox. React Native uses the same model with two important differences:

  • The default flexDirection is "column" (the web default is row).
  • All values are strings: flexDirection: "row", justifyContent: "center".
<View
    style={{
        flex: 1,                    // fill the parent
        justifyContent: "center",   // main axis (column by default)
        alignItems: "center"        // cross axis
    }}
></View>

flex: 1 makes an element take the available space. justifyContent accepts "flex-start", "center", "flex-end", "space-between", "space-around", "space-evenly"; alignItems accepts "flex-start", "center", "flex-end", "stretch".

Safe area

Phones have notches, rounded corners and home indicators that can cover your UI. A safe-area container pads content so it stays inside the visible region instead of sliding under those system features.

import { SafeAreaView, Text } from "react-native";

<SafeAreaView>
    <Text>Content</Text>
</SafeAreaView>

For modern Expo apps you may also use react-native-safe-area-context, which handles notches and system bars more precisely.

ScrollView, FlatList & SectionList

Long lists must be virtualized or the app will stutter. ScrollView renders every child at once (fine for short, static content); FlatList renders only the visible rows and recycles them; SectionList adds grouped, sticky headers (contacts, categories). Prefer FlatList for real data.

import { ScrollView, FlatList, SectionList } from "react-native";

<ScrollView>
    ...
</ScrollView>

// Prefer FlatList for lists
<FlatList
    data={products}
    keyExtractor={(item) => item.id.toString()}   // must return a unique string
    renderItem={({ item }) => <Text>{item.name}</Text>}
/>

// Grouped lists (contacts, categories)
<SectionList
    sections={sections}
    renderItem={...}
    renderSectionHeader={...}
/>

Use ScrollView for a small amount of content and FlatList for real, potentially long lists — it virtualizes rows for performance.

TextInput & state

TextInput is the native text field. Just like web React, bind it to state with value plus onChangeText (React Native's name for onChange) to keep a controlled input.

import { TextInput } from "react-native";
import { useState } from "react";

const [name, setName] = useState("");

<TextInput
    placeholder="Enter your name"
    value={name}             // state drives the field
    onChangeText={setName}   // receives the text directly, not an event
/>

React Native uses normal React state — the same useState model as web React.

useEffect & API requests

Effects and data fetching work the same as on the web — they just run on the device. The common pattern is fetching once when the screen mounts, using an empty dependency array.

useEffect(() => {
    fetch("https://api.example.com/products")
        .then((response) => response.json())
        .then((data) => console.log(data));
}, []);   // [] = run once after mount; add deps to refetch

You can use fetch, axios or RTK Query. Effects, listeners and subscriptions use the same React model as the web. See React State & useEffect.

State management with Redux

React Native can use the same Redux Toolkit store, slices, selectors and RTK Query as a web React app — useful when one MERN backend serves both a web and a mobile frontend.

Full details: Redux Toolkit + RTK Query.

Navigation (Stack & Tabs)

React Native has no browser URLs, so navigation is handled by React Navigation. Screens are pushed onto a stack; tabs switch between top-level areas.

navigation.navigate("Product", { id: product.id });   // push a screen with params
Home
  ↓
Product
  ↓
Checkout
// Read parameters on the target screen
const { id } = route.params;   // the object passed to navigate()

Common navigators: Stack, Tabs (Home | Search | Cart | Profile) and Drawer.

Modal & ActivityIndicator

Modal overlays content on top of the current screen (dialogs, confirmations); ActivityIndicator is the native spinner you show while data loads. Both are visual primitives you will use constantly in mobile UIs.

import { Modal, ActivityIndicator, View, Text } from "react-native";

<Modal visible={isVisible}>   {/* controlled by state, like everything else */}
    <View><Text>Hello</Text></View>
</Modal>

<ActivityIndicator size="large" />

ActivityIndicator is useful for API loading, screen loading and authentication.

Platform, Keyboard & StatusBar

iOS and Android differ in look and behaviour. Platform.OS lets you branch at runtime; KeyboardAvoidingView lifts the UI so the on-screen keyboard does not cover an input; StatusBar controls the system bar at the top.

import { Platform, KeyboardAvoidingView, StyleSheet } from "react-native";
import { StatusBar } from "expo-status-bar";

if (Platform.OS === "ios") {
    console.log("iOS");
}
// Platform.OS is "ios", "android" or "web"

const styles = StyleSheet.create({
    container: {
        padding: Platform.OS === "ios" ? 20 : 10   // per-platform value
    }
});

<StatusBar style="auto" />

KeyboardAvoidingView helps forms stay visible when the software keyboard appears.

Icons & local storage

Expo ships a vector-icon set so you avoid bundling image assets for common glyphs. AsyncStorage is the simple async key/value store (like localStorage) for non-sensitive data such as a theme choice or a flag.

import { Ionicons } from "@expo/vector-icons";

<Ionicons name="home" size={24} color="black" />
// AsyncStorage: simple local key/value data
await AsyncStorage.setItem("token", token);   // persist
const token = await AsyncStorage.getItem("token");   // read back (async)
Warning

For sensitive credentials use a secure storage solution rather than ordinary AsyncStorage.

Image picker, camera & permissions

  • expo-image-picker — profile pictures, product images, uploading photos.
  • Expo camera packages — QR scanning, photos, document scanning.

Mobile apps often need permissions for camera, location, photos, notifications and microphone. Always handle permissions gracefully and explain why you need them.

Environment variables

Don't hard-code secrets. Use an API_BASE_URL variable — for example http://localhost:5000 in development and https://api.example.com in production.

Common mistake

On a physical mobile device, localhost means the device itself, not your computer. Use your machine's LAN IP (or a deployed URL) to reach a local Express server.

Connecting to your MERN API & authentication

The mobile app talks to the exact same Express API as the web app — it simply runs on a device and communicates over HTTP. After login the server returns a JWT; the app stores it in secure storage and sends it in the Authorization header on every later request so protected routes accept it.

React Native
      ↓ HTTP
Express API
      ↓
MongoDB
      ↓ JSON
Mobile App
Login → Express API → JWT → store token
      → send token with requests → protected API
Authorization: Bearer TOKEN

Store authentication tokens using secure storage. The server-side protect middleware and token signing live in Authentication & JWT, and the endpoints in REST API.

Custom components, props & structure

Structure a React Native app exactly like a React web app: small components that accept props, screens that compose them, and shared services. Create one reusable Button instead of repeating Pressable everywhere.

function Button({ title, onPress }) {   // same props model as web React
    return (
        <Pressable onPress={onPress} style={styles.button}>
            <Text style={styles.text}>{title}</Text>
        </Pressable>
    );
}

function ProductCard({ name, price }) {   // another reusable component
    return (
        <View>
            <Text>{name}</Text>
            <Text>${price}</Text>
        </View>
    );
}

<ProductCard name="Laptop" price={1200} />

Conditional rendering is the same as React:

{loading && <ActivityIndicator />}

{user ? <Profile /> : <Login />}

A typical project structure:

src/
    components/   Button.jsx  Card.jsx  Header.jsx
    screens/      HomeScreen.jsx  LoginScreen.jsx  ProfileScreen.jsx
    navigation/   AppNavigator.jsx
    services/     api.js
    store/        store.js  authSlice.js

Create a reusable <Button /> instead of repeating <Pressable> everywhere. Props work exactly as in web React (see React → Props).

Animation (Reanimated)

React Native ships with Animated, but modern apps use React Native Reanimated for professional animation. The concept: a shared value drives an animated style, which produces a UI animation.

Shared Value
      ↓
Animated Style
      ↓
UI Animation
Warning

GSAP is primarily designed for web/DOM/SVG. For native mobile animation, reach for Reanimated instead. Web animation is covered in GSAP.

Gestures (swipe, drag, pan, pinch, long press) commonly use React Native Gesture Handler, often combined with Reanimated.

Performance

  • Avoid unnecessary re-renders.
  • Use FlatList instead of rendering huge lists manually.
  • Optimize images.
  • Avoid expensive calculations during render.
  • Use memoization only when there is a real, measured need — don't optimize prematurely.

Debugging

Use console.log(), React Native DevTools, Expo development tools, Android Studio tools, and Xcode tools (macOS/iOS). Inspect network requests, state, props, errors and performance.

React Native vs React web vs HTML/CSS

React webReact Native
<div><View>
<p><Text>
<button><Pressable> / <Button>
<input><TextInput>

Both use components, props, state, hooks, context, Redux and API calls. But where HTML provides structure and CSS provides web styling, React Native renders native components styled with JavaScript objects.

<!-- Web -->
<div className="card"></div>

<!-- React Native -->
<View style={styles.card}></View>

Base element semantics are covered in HTML; styling concepts in CSS.

MERN + React Native

One backend can serve a React web client and a React Native mobile client at the same time, because both speak the same REST API. Express, Node and MongoDB stay the single source of truth, so adding a mobile frontend requires no server changes.

                 MongoDB
                    ↑
                 Express
                    ↑
                  Node
                 /    \
                /      \
          React Web   React Native
             ↓             ↓
           Browser       Mobile

One backend can serve both applications. See MERN Architecture for the full picture.

Full counter example

The whole flow in one file — local state, a Pressable handler and StyleSheet styles — tying together everything on this page.

import { View, Text, Pressable, StyleSheet } from "react-native";
import { useState } from "react";

export default function App() {
    const [count, setCount] = useState(0);   // the screen's local state

    return (
        <View style={styles.container}>
            <Text style={styles.title}>Count: {count}</Text>

            <Pressable
                style={styles.button}
                onPress={() => setCount(count + 1)}   // re-render with +1
            >
                <Text style={styles.buttonText}>Increase</Text>
            </Pressable>
        </View>
    );
}

const styles = StyleSheet.create({
    container: {
        flex: 1,
        justifyContent: "center",
        alignItems: "center"
    },
    title: {
        fontSize: 24,
        fontWeight: "bold",
        marginBottom: 20
    },
    button: {
        backgroundColor: "#4f46e5",
        paddingVertical: 12,
        paddingHorizontal: 24,
        borderRadius: 8
    },
    buttonText: {
        color: "white",
        fontSize: 16,
        fontWeight: "600"
    }
});

Quick recap

  • Use Expo: create-expo-app then expo start.
  • Native components: View, Text, Image, Pressable, TextInput.
  • Style with StyleSheet.create and JavaScript objects.
  • Flexbox concepts come from CSS; default direction is column and flex: 1 fills space.
  • FlatList for lists, React Navigation for Stack/Tabs.
  • State/hooks/Redux/RTK Query are the same as web React.
  • Connect to the MERN API with a configurable base URL, and remember localhost means the device.
  • Animate with Reanimated (GSAP is web-only); handle permissions and secure storage carefully.
